# 审查升级轮 25（2026-09-22）：剧本审查循环必崩修复 + finalize 终审闸

> 本轮两个发现都来自独立子智能体对审查链的缺口审计（用户最初要求的
> 「多用子智能体」工作方式），均经我在本地逐行复现实锤。

## 25a：`_iterate` 引用三个未定义变量——剧本审查循环 100% 必崩

`pipeline_runner._iterate` 的「时长意图闭环收尾」块引用了三个在函数内
**从未赋值**的变量：`fitted_total`（:429）、`dev`（:430）、`llm_meta`
（:439）。而 `stage == "script"` 且 brief 带 `duration_sec`（brief 审查
强制该字段必填）时 `dur_target > 0` 恒成立 → **每轮剧本迭代结束必抛
NameError**。本地最小复现：

```
crash-repro: _iterate("script", ...) → NameError: name 'fitted_total' is not defined
```

后果：`/api/pipeline/text` 500，剧本阶段的审查循环（规则 + LLM 审片 +
时长 intent critical）整条链路形同不存在——不是放过缺陷，是门本身没跑。
该路径无任何测试覆盖（E2E 从外部 prime 文本阶段，绕过了 `_iterate`）。

**修复**：`_fit_duration_to_target` 改为返回三元组
`(data, reachable, meta)`（meta 外泄内部已算好的 fitted/dev，单一日真
源）；`_iterate` 用 meta 定义 `_fitted_total`/`_dev`/duration 元数据。
3 个既有测试解构点同步更新。

**回归**：`TestIterateDurationLoop` 2 例钉住可达/不可达两条路径——
不崩 + 不可达路径必须产出「无法收敛」duration critical + 可达路径
metadata.duration.fitted 正确。

## 25b：finalize 从不读终审结论——fix 的成片照样能发布

`project_finalize`（api.py）只查 brief/script/storyboard/video_gen/
post_production 五阶段 PASS + script 确认，**从不读 final_review.json**。
而 pipeline 的 assemble 在终审非 pass 时返回 released=False——但
post_production 早在第 6 步（mux 后、终审前）就记了 PASS。于是带着
VLM 断帧 / BRAND_MISSING / timeline REUSE 红线 / 旁白缺失 / 单镜与
入拼 critical 的成片，一个 `POST /api/project/{id}/finalize` 就变
RELEASED——**轮 9-24 所有门的阻断都在发布入口被绕过**。未跑过
assemble（无 final_review.json）的项目同样能被发布。

附带修掉：原实现在发布时把 post_production 的 artifact_hash 覆写成
字面量 "RELEASED"——pipeline_runner 早已避开这个坑（注释明载会导致
后续哈希校验永远 409），API 路径一直在犯。

**修复**：finalize 追加终审闸——`final_review.json` 缺失 →
`NOT_REVIEWED` 拦；verdict≠pass → 带上 verdict/critical 数/reason
拦（409 UPSTREAM_FAILED）。发布时保留原成片完整性指纹，发布事件走
`record_event`（与 pipeline 一致）；指纹为空（旧数据）才退回字面量，
避免 record_artifact 的 EMPTY_HASH 500。

**回归**：`TestApiGates` 3 例——fix 拦（409 且 gate 带 critical=1）、
无终审拦（NOT_REVIEWED）、pass 放行且 artifact_hash 不被覆写。
