# 轮51：字幕宽度治本 2.0——真字体度量折行（E2E 第 8 次唯一卡点）

日期：2026-09-23。E2E 第 8 次复跑取得历史最大进展：**变体 generate
十镜全过、进到 assemble**，最终挂在字幕验收门：

```
字幕验收未过(§10.6): cue2:宽度63.7%超红线≤62%; cue4:65.4%; cue5:63.7%
```

## 根因：字符预算对 CJK 系统性低估

轮44d 的折行按字符数估算（`max_line_chars = int(0.62×1280/46) = 17`），
假定 1 字 = 1 em。但 drawtext 实际渲染用的 CJK 字体（msyh）advance
实测 ≈48px/46px 字号（1.043 em）——17 字 = 816px = **63.7%** 屏宽，
恰好踩穿 62% 红线。字符预算公式整体低估 ~4.3%，长句（17-18 字）必挂。
验收门量的不是估算而是渲染墨迹 `(xmax-xmin)/视频宽`，所以拦得准、
但生成侧永远折不够。

## 修复（三层）

1. **`subtitle_renderer.measure_text_px`**：用 drawtext/libass 实际
   解析的**同一字体**（`_resolve_font_path`）度量像素宽（PIL
   textlength）。字体对象与 Draw 单件按 (path, size) 缓存——
   逐字符度量下每次 truetype 加载会让 40 字长句折行慢一个数量级
   （实测 300 句 >120s → 1.5s）。
2. **`pipeline_runner._wrap_to_width`**：主路径改像素预算
   （assemble 传 `int(0.62×屏宽)`），每行实测 ≤ 预算；折点取最后
   一个可容纳前缀内的标点（留上行尾）。两个排版禁则后处理：
   - **行首禁则**：折点产出「，从这里开始」这类行首标点时，标点
     上移行尾；行1 顶格放不下则借一个**非标点**字符下来腾位
     （「…时刻 / ，从这里开始」→「…时，/ 刻从这里开始」）。
   - **孤字消隐**：硬切出的 1 字末行（「适」）从上行借非标点字符
     补到 ≥3 字。
3. **回退链**：PIL/字体不可用 → measure 返回 None → 回退轮44d 的
   字符折行（`max_line_chars` 保留为兜底参数，assemble 两个都传）。

## 过程中修掉的两个真 bug（fuzz 逼出来的）

- **禁则循环死锁**：borrow 分支在「行尾标点 ↔ 行首标点」都是标点
  时乒乓无进展（40 字标点串实测挂死）。修：borrow 只搬非标点 +
  迭代上限。
- **尾随空白孤行**：text 入口 strip + 丢弃纯空白行。

## 测试

`TestSubtitleWidthWrap`（6 例）：长句折到 ≤62%；17 字单行放得下
（61.1%）不被误折；折后无行首标点；无 1 字孤行；字体不可用回退
不炸；assemble px 模式下每条 cue 每行实测 ≤62%。另 309 例 fuzz
（含全标点串/无标点长英文/随机中英混排）零超宽。

## 遗留

- 折行预算用 62% 全量（度量即渲染字体），无额外安全余量；drawtext
  与 libass 两条烧录路径的度量若有个位像素差，验收门仍会诚实拦截
  ——届时再收 1-2% 余量即可。
- E2E 第 9 次复跑待发（generate 已全过，这是最后一关）。
