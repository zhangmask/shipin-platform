# 审查升级轮 28（2026-09-22）：语义审片不可用不得静默放行

## 缺口：「审不了」被当成「审过了」

`_iterate` 对 script/storyboard 阶段跑完规则引擎后调
`llm_stage_review` 做语义审片（故事四拍结构、单动作可拍性、镜间连续性、
主角描述逐字一致、品牌贯穿）。但 `llm["available"]` 为 False 时
（AGNES_KEY 中途失效、端点 5xx、输出两次不可解析）**旧代码什么都不
记**：decision 维持规则引擎的结论——纯规则 pass 就直接进花钱的生成
阶段，语义审查整轮无人做。入口的 key 预检只挡「开始时没有 key」，
挡不住运行中失效。

## 改动（pipeline_runner.py `_iterate`）

语义审片不可用时：

1. `llm_info` 落 `{"available": False, "reason"}`（此前 llm_info 停在
   `{}`，信号整个丢失）；
2. 追加 warning finding（dimension=`llm_review`，issue 注明不可用原因
   与「只过了规则引擎」的事实，revision_strategy=retry）；
3. **决策强制离开 pass**：原为 pass / pass_with_warnings → revise
   （重试；max_rounds 后 stop 人工介入）。与轮 25 时长门的处理同构——
   审不了 ≠ 审过。
