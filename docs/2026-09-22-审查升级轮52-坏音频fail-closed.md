# 轮52：坏音频 fail-closed（九审 P3-6 收口）

日期：2026-09-23。第 9 轮审计遗留 P3 项修复。

## 问题

`align_narration` 的旁白/台词轨时长探测走 `_ffprobe_duration`——旧实现
`float(r.stdout.strip() or 0)`：ffprobe 对**损坏/不可解码**的 mp3
（截断、写作中断、二进制垃圾）输出空 stdout → `or 0` 兜成 0.0 →
align 的存在性检查（文件在）通过、`voice_tail=0` → window=sb_dur、
零 finding、verdict ok。而真实音频长度无约束，直接在终点前被截/
压顶下一镜。这是 align 门对「坏音频」的 fail-open：**测不出 ≠
没有**。另 ffprobe 二进制缺失时 subprocess.run 的 FileNotFoundError
无人接（tts_service 侧反而兜了）→ 500 而不是 verdict。

## 修复（assembly.py）

- 新 `_probe_voice_duration(path) -> Optional[float]`：人声轨专用
  探测——空输出/"N/A" 解析失败、OSError（ffprobe 缺失）都返回
  None（探测失败），与"探测到 0 秒"明确区分。修掉 `or 0` 把
  空 stdout 兜成 0.0 的自欺路径。
- `align_narration` 的人声轨改用它：文件存在但测不出 → critical
  `VOICE_PROBE_FAILED`（fail-closed，与 NARRATION_MISSING 互补：
  前者是"没有"，后者是"有但不可信"）。视频时长类的其他调用方
  （stitch/subtitle/kenburns）继续用 `_ffprobe_duration`——它们的
  失败模式另有守卫，不在本变更面内。
