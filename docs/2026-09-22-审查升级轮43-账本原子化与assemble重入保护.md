# 审查升级轮 43（2026-09-22）：账本原子化 + assemble 重入保护（七审 #5/#6）

## 43a：成本账本从“静默清零”到“损坏即止”（七审 #5）

`costing` 旧实现三个洞：`record_cost` 读-改-写全程无锁（异步任务
`ThreadPoolExecutor` 并发 record_cost，后写覆盖先写——少计费且两次
都真花了钱）；`write_text` 截断式写（磁盘满/进程被杀写在半路留损坏
JSON）；`_load_rows` 损坏时**静默返回 []**——预算闸判定"没花钱"重新
放行，`seq` 从 1 重记，历史账目无声消失。**账本清零 = 给预算闸开后门。**

**修**：进程内 `threading.Lock` 包住读-改-写；写改 `mkstemp +
os.replace` 原子写；损坏时**备份**（`cost.corrupt-<ts>.json`）并抛
`LedgerCorruptError`，调用方必须显式处理。

## 43b：assemble 重入不再覆盖已发布成片（七审 #6）

旧代码 mux/normalize 直接写 `final.mp4`：项目已 released → 改分镜 →
重跑 assemble 卡在任一步 → 盘上 `final.mp4` 变成未归一化甚至截断的
中间产物，而 store 里 post_production 仍 PASS、事件流仍写着"成片已
发布"——**发布态与盘上文件脱节且不可回滚**。

**修**：mux→normalize 全部写 `final.candidate.mp4`，全部成功后才
`os.replace` 原子上岗；替换前把旧 `final.mp4` 挪存为
`final.published.mp4`（可回滚）；失败路径不动旧片。顺带把 `_save`
也改原子写（轮 32a 把 record_artifact 挪到 `_save` 之后，半截 JSON
会让"DB 说审过、盘上是坏的"）。

## 43c：预算闸/熔断对账本损坏显式处理

`_enforce_budget`（api.py）与 `_budget_exceeded`（阶段内熔断）都
捕获 `LedgerCorruptError`：入口闸返回 422 并指明修复路径（绝不静默
放行）；熔断方向取"停"——查不了账就不能继续花钱。

## 测试（intent 40/40、hardening 113/113）

- 截断的 cost.json → `LedgerCorruptError` 且留下 `.corrupt-*` 备份；
- 两笔 record_cost → seq 1,2 连续、无 `cost.tmp-*` 残留；
- `_save` 后文件可 `_load` 且无 `.tmp` 残留。
