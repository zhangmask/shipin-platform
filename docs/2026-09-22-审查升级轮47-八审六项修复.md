# 轮47（八审驱动）：六个实锤——覆盖被同 run 覆盖、协议失败判 ok、checked 虚报、纯台词镜不可出片

日期：2026-09-23。第 8 轮独立子智能体审计（读代码 + 可执行复现），本轮修复 6 项。

## 修复清单（每条均带新过/旧挂验证）

### P0-1 keyframe 门的 critical 被同 run 旧内存字典覆盖（pipeline_runner.py）
- 病：generate 循环前 L904 一次性加载 `shots_review`；keyframe 分支
  （L936-952）另起 `_load` 新副本写 `__keyframe_{sid}__` 并保存；随后
  该镜 qc=ok 分支用**循环前的旧字典**整体 `_save`（L1064），把刚写的
  keyframe 条目从文件里抹掉。
- 果：happy path 下 `KEYFRAME_MISMATCH` critical 100% 到不了终审
  （assemble 的 `_sr_all` 读不到、review_channels 的 keyframe 通道从不
  出现）；只有该镜三连败提前 return 时 finding 才侥幸留在文件里。
- 修：keyframe 分支改写进循环内共用的 `shots_review` 内存字典并立即
  落盘，两条出口（qc=ok 保存/失败路径保存）都带着它。
- 测试：`test_keyframe_critical_survives_successful_generation`。
  **测试隔离教训**：固定 pid 的项目目录跨运行残留会让 L904 的 `_load`
  把上一轮（修复后）的 `__keyframe_*` 条目带进内存，把覆盖 bug 掩盖
  掉——测试必须先清场（rmtree）再跑，本次因此加过一层才抓到旧挂。

### P0-2 check_keyframes 协议失败返回 verdict "ok"（hard_gates.py）
- 病：无 AGNES_KEY / VLM 整批不可用 → checked=0、findings=[]、
  verdict="ok"，调用方把 `keyframe_review="ok"` 写进 manifest——
  "没审到"被记成"审过了"，与 vlm_review_final 的 blocked 约定不一致。
- 修：无 key → `verdict="blocked"` + `available=False`（不进 findings、
  不并审）；单镜 VLM 不可用单独计数 `unavailable`；整批零判定 → blocked；
  部分不可用 → warning `KEYFRAME_UNVERIFIED`（不升 critical，一次
  hiccup 不毙片；也不静默）。旧固化测试 `test_no_key_skips` /
  `test_unparseable_payload_not_a_verdict` 的错误断言已修正。
- 测试：4 个新测（无 key / 整批不可用 → blocked；缺帧仍 ok+skip；
  部分不可用 warning 且 verdict 保持已审结论）。

### P1-1 check_narration_presence 在 ffmpeg 不可用时整门判 ok（hard_gates.py）
- 病：`_silence_spans` 把 subprocess 起不来吞成 `[]` → 调用方读成
  "处处有声" → 所有台词窗口判 ok；`_has_audio_stream` except→True 让
  NO_AUDIO_TRACK 也不报。协议失败冒充判定（手工链单跑音频门时无其它
  门兜底）。
- 修：`_silence_spans` 协议失败显式抛（spawn 失败 / rc≠0），调用方转
  `verdict="blocked"` + `available=False` + warning `NARRATION_PROBE_FAILED`。
- 测试：ffmpeg 缺失（FileNotFoundError）与 rc≠0 两条路都 blocked。

### P1-2 身份一致性通道 checked/intra_checked 虚报（hard_gates.py）
- 病：`checked += 1` / `intra_checked += 1` 在 available 检查**之前**——
  VLM 协议失败（captured=True、available=False）也计入，final_review.json
  的 identity 报「比对过且通过」而实际 0 个判定。
- 修：计数只在拿到判定后自增；新增 `unavailable` 计数；整通道零判定
  （有任务全失败）→ critical `IDENTITY_UNVERIFIED`（没审到 ≠ 审过了）；
  部分失败不冒充通过也不禁发。旧固化测试
  `test_malformed_same_person_payload_not_a_verdict` 的 `intra_checked
  == 1` 断言已修正。
- 测试：全失败 → critical + checked=0；部分失败 → checked=1 无 critical。

### P2-2 纯台词镜使 generate 误报 "TTS 缺失"（assembly.py + pipeline_runner.py）
- 病：剧本模板允许「每镜 narration 或 dialogue 至少其一、全片至少 2 镜
  dialogue」。纯台词镜只合成 `{sid}_dlg_*.mp3`，而 `_tts_of` 的 glob
  排除 `_dlg` → None → generate 返回 `S0x TTS 缺失`：**合法剧本永远
  无法出片且报错指错方向**（运营去查 TTS 服务而非脚本形态）。align 层
  同样只要 narration_path 空就判 NARRATION_MISSING。
- 修：assemble 检查循环对"两条人声都没有"才拦；台词轨就是该镜人声，
  manifest 不写 tts 键（assemble 声床对 narr/dlg 各自独立可选）；
  align 的 NARRATION_MISSING 只在旁白台词都缺时触发；`_tts_fresh`
  给台词镜新鲜度路径（台词轨在+指纹匹配即新鲜，不每次重合成）。
  align 调用处 `["tts"]` 改 `.get`（纯台词镜无此键，防 KeyError）。
- 测试：generate 级（两镜：S01 纯台词非末镜/S02 常规——末镜会被
  `_bind_brand` 强制写品牌旁白，那是品牌确定性通道的设计行为，单镜
  种子曾因此误判）+ align 级正反两向。
- 注意：`_bind_brand` 只强制**末镜**旁白，非末镜纯台词镜才是本 bug
  的现场。

### P2-1 timeline 覆盖模型 at=narr_at（hard_gates.py + pipeline_runner.py）
- 病：check_timeline 覆盖公式 `at + (end-start)` 契约是「at=片段起点」，
  但 pipeline 传的是 narr_at（台词镜旁白在台词+0.18s 后才开口）→ 末镜
  带台词时覆盖高估 dlg+0.18：掩盖最多该量的真实亏长（短片变 ok），
  偏差 >3% 时又误拦（短片+长台词）。
- 修（双约定并存，api /timeline 端点走 legacy 元组约定 start/end 是
  clip 内相对量）：**调用方**恢复契约传窗口起点为 at；**门**兼容
  `end > at` 时 end 即绝对边界，否则 `at + (end-start)`。两向都正确。
- 测试：末镜台词镜覆盖精确（不虚高 0.18s）；亏长不被 narr_at 掩盖。

### P3 _clip_is_pooled 把项目子目录也算池（pipeline_runner.py）
- 病：判据只比 `parent != 项目目录`——项目**子目录**里的 clip
  （stitch 落 part 的 work/parts/ 等）被判池化，而池化分支新鲜度
  **不比 prompt 指纹**，配合深拷贝 manifest 的 stale qc==ok +
  clip_shot_sha 可把任意旧 clip 塞回时间线。
- 修：`not c.is_relative_to(proj)`——目录树内 = 本地产物（全输入
  指纹），树外 = 池（定义指纹）。前缀相似目录（coffee-v7x）不误判树内。
- 测试：4 个（子目录非池 / 根目录非池 / 他项目为池 / 前缀目录为池）。

### P4 _extract_frames 的 times[:count] 丢片尾锚点（hard_gates.py）
- 病：候选 count+2 个点（首锚 + count 铺点 + 尾锚）后 `[:count]` 按
  排序砍掉**最大**的几个——docstring 许诺的 "start + spread + end"
  里片尾锚点恒丢失。注意**整数倍时长下结尾侥幸幸存**（dur=30、
  count=12 时铺点恰好落在 30.0），非整数倍（31s）才暴露：被砍的
  正是 30.5/31.0，片尾 2.6s 无帧。
- 修：钉住首/尾锚点，中间 count-2 个铺点均分；短片首尾重叠去重保序。
- 测试：31s/12 帧尾锚点 ≥30.0 且间隔均匀；短片去重。
