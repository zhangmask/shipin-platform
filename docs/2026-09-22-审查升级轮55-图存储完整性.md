# 轮55：图存储完整性（十审 P0×2/P1×2）——project_id 穿越写、save_graph 原子化、gid 碰撞、asset 串台

日期：2026-09-23。第 10 轮独立审计（主攻 reference 链/画布 API/whisper/
finalize），本轮修 2 个 P0 + 2 个 P1。

## P0-1 project_id 无白名单 → 任意目录穿越写（pipeline_runner.py + api.py）

- 病：`_project_dir` = `PROJECTS_DIR / project_id`，project_id 只经过
  `stage_store._require_project()`（只查非空）。`_save('../../pwned', …)`
  实测写到**仓库根** `pwned/brief.json`，`'/abs'` 写到**磁盘根**
  `D:/abs/brief.json`；`_load`/`read_version` 同样可从任意目录读回 →
  信息泄露 + 任意位置写 JSON。端点路径：
  `POST /api/project/create {"project_id": "../../pwned"}` →
  `POST /api/pipeline/../../pwned/restore`（URL 编码由路由透传）。
  同仓 `engine._safe`、`api_reference._SAFE_NAME` 都有白名单，这里是
  唯一漏网的 id 入关。
- 修（两层）：`_safe_project_id`（`[A-Za-z0-9_-]{1,64}`，否则
  ValueError）进 `_project_dir`——所有 `_save`/`_load` 自动受护；
  api.py 中间件对 `/api/(pipeline|project|variant)/{id}` 路径 id 先过
  白名单，不合法直接 422（与既有 403 绑定检查并列）。
- 验证：既有 2098 个项目目录全部合规（零误伤）；新测覆盖
  `../../pwned`/`/abs`/`..`/`a/b`/空格/超长 → ValueError，正常 id
  放行，`_project_dir` 结果恒在 PROJECTS_DIR 下。

## P0-2 画布 save_graph 非原子 + lost update（engine.py + api_graph.py）

- 病：`save_graph` 裸 `write_text` 全量覆写 `graph.json`：(a) 磁盘满/
  进程被杀留半截 JSON → `load_graph` 之后 `json.loads` 裸抛 500；
  (b) 两个并发操作（PUT / add / patch / delete / run 收尾）各拿旧快照
  互相覆盖——实测 8 线程并发 add_node **只剩 1 个节点**。
- 修：`save_graph` 改 tmp + `os.replace` 原子写；新增按 gid 细分的
  `graph_write(gid)` 上下文锁，api_graph 的全部变更端点
  （PUT/run/run-all/add-node/del-node/patch-node）把 load→改→save
  全程裹进锁——lost update 的根源是 RMW 周期而非写本身，只在写里加锁
  治不住。单进程部署（start.sh/Dockerfile 均无 --workers）下进程内锁
  足以消除；`_GRAPH_LOCKS` 按图细分，不同图互不阻塞。
- 测试：8 线程走 API 并发 add_node → 8 节点全留；原子写无 .tmp 残留。

## P1-1 图 id 秒级碰撞（engine.py）

- 病：`new_graph` 用 `g-YYYYMMDDHHMMSS`——同秒两次创建拿到同一 gid，
  第二次 save_graph 覆盖第一个，先建画布的节点/边/产物静默丢失
  （外部 AI 批量建画布/前端双击/reference apply 并发都可达）。实测
  同秒两图，`load_graph(g1)` 得到 g2 的名字和 0 节点。
- 修：追加 uuid8 后缀（`g-<ts>-<uuid8>`），时间戳保留可读性。
- 测试：同秒连建 20 个图 id 全异。

## P1-2 graph_asset 前缀 glob 串台（api_graph.py）

- 病：`sorted(root.glob(f"{safe}*"))[0]`——无 `_` 分隔前缀 glob：
  `'n10_bbbb.mp3' < 'n1_aaaa.mp3'`（'0' 0x30 < '_' 0x5F）→ 节点 n1
  读到 n10 的产物。与九审在执行器侧修掉的「画布 tts 串音频」同类，
  但**执行器修了、读侧端点漏了**。附带修复：`safe_node` 把 '.' 也剥，
  导致 docstring 承诺的 `im1.png` 形态查询永远 404。
- 修：查询名清洗保留点；精确名（带扩展名）优先；否则按
  `{stem}_*` 分隔前缀 + mtime 取最新；resolve 前缀校验保留。
- 测试：n1/n10 产物共存各自解析正确；`n1.png` 精确命中。
