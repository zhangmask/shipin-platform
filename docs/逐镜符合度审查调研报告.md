# 「剧本/分镜 vs 生成视频」符合度自动审查 —— 业界调研与落地建议

> 调研日期：2026-09-21；方式：GitHub API / GitHub 网页 / arXiv API 实读源码与摘要。
> 结论速览：**业界没有公开端到端「分镜当检查清单、逐镜 VLM 回对」的成品仓库**——但所有组成件都有开源实现，且 2024-2026 的最新评测范式（SemComp-Bench、VQ-Insight、Vript-HAL/ERO）与你要做的完全同构。建议直接采用「确定性客观检查（CLIP/检测/ASR/SyncNet）+ 中文 VLM 逐镜结构化 JSON 裁判」的两段式组装，下面给出可直接搬的代码、提示词与阈值。

## A. 逐镜符合度审查评分维度表

每个维度按「输入 → 算法/VLM 提示 → 失败码 → 严重度」给出。模型来源列是经实读源码确认的实现者。

### A1. 确定性/客观量化维度（低算力、可批量、先跑）

| 维度 | 输入 | 算法参考（可搬代码） | 失败码 | 严重度 | 备注 |
|---|---|---|---|---|---|
| 全局图文一致性（"整体像不像"） | 镜内抽 8 帧 + 分镜文本 | **ViCLIP** 视频-文本特征余弦相似度，逐视频取均值（VBench `overall_consistency.py` 原样逻辑）；或 CLIP ViT-B/32 帧均值 | `TEXT_ALIGN_LOW` | LOW（辅助） | 只回答"整体像不像"，**不知道哪不对**；适合做粗筛/回归监控，不适合拦截 |
| 逐刻度细粒度文本对齐 | 该镜文本 + 抽帧 | T2VScore 的 aT2VS 路线：CLIP 全局相似度 + VLM 对"文本中的每个名词/动作短语是否出现在画面"打分后加权 | `TEXT_ALIGN_BAD` | HIGH | 这是从"整体相似"走向"逐点核对"的第一步 |
| 主体一致性（跨帧不变） | 镜内 N 帧 | CLIP 帧对余弦（VBench `background_consistency` 用 CLIP、`subject_consistency` 用 DINO），取平均 | `SUBJECT_DRIFT` | HIGH | 抓"脸/产品换人换样"类漂移 |
| 时序闪烁 / 卡顿 | 全帧 | 相邻帧 MAE 均值（VBench `temporal_flickering`，目标为静态/弱动区）；动态度用 RAFT 光流 top-5% 量级阈值 6.0（VBench `dynamic_degree`） | `FLICKER`/`DYNAMIC_DEAD` | MEDIUM | 动态度太低 → "静止PPT感"；太高 → 与动作指令冲突（配合 MOTION 检查） |
| 运动平滑度 | 全帧 | DMT 视频插帧对齐分数（VBench `motion_smoothness` 用 AMT 插值器算 VFI score） | `MOTION_JANKY` | LOW（可只记日志） | 与"动作对不对"无关，是"动作顺不顺" |
| 动作类别 | 镜内 16 帧 | Kinetics-400 视频模型 top-5 sigmoid ≥0.85 才算命中（VBench `human_action`，UMT ViT-Large）。**局限：只有 400 类有限集合，写不出"推开头喝牛奶"这种细动作** | `ACTION_MISMATCH`(客观版) | MEDIUM | 与 VLM 动作判断互为补充：客观版抓"大类错" |
| 物体在场/多物体 | 抽帧 | GRiT（DenseCaptioning 目标检测）检测出的物体表 vs 文本名词表，做 CLIP 相似度和/或 IoU 匹配（VBench `object_class`/`multiple_objects`/`color`/`spatial_relationship`，后者用 bbox IoU 判左右/上下关系） | `OBJECT_MISSING` / `OBJECT_EXTRA` / `SPATIAL_MISMATCH` | HIGH（缺关键物）/MEDIUM | 中文字、中文 prompt 下的名词抽取用分词器先翻 |
| 画面字幕文字（落版字/品牌字） | 抽帧 OCR | PaddleOCR（EvalCrafter 自带 `metrics` 目录有现成封装）；比对预期落版文案 | `TEXT_PLATE_MISSING` / `TEXT_TYPO` | BLOCKER（若该镜是落版镜） | 落版字错/缺 = 必须重渲染 |
| 镜头重复/复用 | 相邻镜帧间 CLIP/DINO 余弦 | 同 A1 主体一致性代码对「相邻两镜」计算；低于阈值=镜头复用 | `SHOT_REUSE` | BLOCKER（安全红线，你已设） | 已有，不作新实现 |
| 成片总时长与分镜骨架总时长 | 分镜明细 | 逐镜时长累加 vs 成品时长，差>容差 | `LENGTH_DRIFT` | LOW | 附带抓"整条剪辑丢帧" |

### A2. VLM 裁判维度（每镜一次结构化问答，见 B 模板）

| 维度 | 输入 | VLM 判定要点 | 失败码 | 严重度 |
|---|---|---|---|---|
| 场景正确性 | 分镜 scene 字段 + 该镜首/中/末帧 | "画面是否是台词/分镜描述的场景与时间段（如 客厅/白天/城市夜景）" | `SCENE_MISMATCH` | HIGH |
| 主体正确性 | 分镜 subject 字段 + 帧 | 主体（演员/产品/角色）必须出现在画面且是画面主角；出现他人角色顶替 | `SUBJECT_MISMATCH` | BLOCKER（主角一口出镜必拒） |
| 动作/表演 | 分镜 motion + substantiation 帧+部分中间帧 | 预期动作是否"可见地发生"（如 转身、举杯、奔跑）；抓"静止场景贴激活"（动作被画成静态） | `ACTION_MISMATCH` / `MOTION_MISMATCH` | HIGH |
| 机位/运镜 | 分镜 camera 字段 + 首末帧 | 机器部+运镜方向与字段一致（推/拉/摇/移/跟/固定）；**业界无成熟客观做法**（最近 ShotVerse 等只是可控生成方向），VLM 足矣 | `CAMERA_MISMATCH` | MEDIUM（对品牌镜头可提 HIGH） |
| 缺了物体 / 多出物体 | 分镜 objects（若分镜里有）+ 帧 | 登记漏判缺一物件 / 出现侵入性物件（祖传文案画风乱入） | `OBJECT_MISSING` / `OBJECT_EXTRA` | HIGH / MEDIUM |
| 空间关系/布局 | 分镜 composition/布局 字段（如有）+ 帧 | 左右/上下/前后位置关系 | `SPATIAL_MISMATCH` | MEDIUM |
| 镜头缺失(整条丢失) | 成片关键帧 + 全部分镜 | 见 C 模板：哪些镜找不到内容对应 | `ORDER_DROPPED` | BLOCKER |
| 镜头顺序错置 | 同上 + 分镜序号 | 成片里镜出现先后与分镜不一致 | `ORDER_ASC` (同样用 C 模板输出) | HIGH |
| 关键镜头(强制出现镜)存在性 | 关键镜定义（落版/品牌特写/主角出场/开场 3 秒） | 见 B 模板 2：需做到"绝对存在性判定"，不依赖"整体像不像" | `KEY_SHOT_MISSING` | BLOCKER（一票否决） |
| 台词说白与画面动作 | ASR 结果 + 帧 | "旁白说『他/她举杯』而画面没举杯" | `NARRATIVE_ASYNC` | MEDIUM |
| 口型与音频 | 音轨+嘴 | SyncNet 确定性判定（见 B 模板 4 说明）；舌口型逐字贴合太学术，工业上把 | `LIP_ASYNC` | LOW（嘴型差一点）/ HIGH（完全错位 >0.3s） |
| 超自然/幻觉 | 帧 | 物体穿过、倒置、字乱码、多人重叠——开漏检查 | `VISUAL_HALLUCINATION` | HIGH |

> 严重度语义：BLOCKER = 不改不产出；HIGH = 需人工/自动重生成该镜；MEDIUM = 记日志进总检；LOW = 不过红盘。
> 权重聚合建议：`镜头级 PASS` 条件 = 无 BLOCKER + HIGH ≤0 + 任何 MED 都需单条说明；成片级 PASS = 关键镜头全部存在 + ORDER 全序正确 + 总 FAIL 数/shot 数 ≤ 6%。

## B. VLM 提示词模板（可直接给中文 VLM 使用，如 agnes-3.0-flash）

> 使用要点：temperature=0；`response_format=json`（若支持）；每镜独立并行调用；采样帧带**时间戳**写进图里；结果写死 JSON schema 校验，schema 不过就重试一次（第二次仍不合法 = 该镜置 UNVERIFIABLE，转人工）。
> 帧采样：首帧、中帧、末帧 + （镜长>4s 时）每 1.5s 补一帧，≤8 帧一次。

### B1. 逐镜符合度核对（主模板，中英）

```text
[系统]
你是影视成片质检员。输入：一条"分镜指令需求"和"成片中对应镜头抽出的若干帧画面（带时刻 t）"。
请逐项核对，只输出一个 JSON 对象，不要输出其他文字。

# 中文版
{
  "shot_id": "<分镜编号>",
  "checks": {
    "scene":  {"ok": true, "note": "画面主场景/时段是否与分镜一致"},
    "subject": {"ok": true, "note": "指定主体(演员/角色/产品)是否出现且是画面主体"},
    "action": {"ok": true, "note": "指定动作/运动是否在画面中真实发生"},
    "camera": {"ok": true, "note": "景别与运镜(固定/推/拉/摇/移/跟/环绕)是否一致"},
    "objects": {"ok": true, "missing": ["...", "..."], "extra": ["...", "..."], "note": ""},
    "text_overlay": {"ok": true, "expected": "<落版文案或''>", "note": "OCR 结论"},
    "continuity": {"ok": true, "note": "与前序镜头衔接有无跳变/穿帮/风格突变"}
  },
  "obvious_issues": ["画面扭曲", "穿模", "字幕错字", "无"],
  "verdict": "pass",     // pass | fix
  "fix_reasons": ["<最严重问题的短语，最多3条>"],
  "evidence": [{"t": 1.2, "what": "可见产品正面特写"}]
}
判定规则:
- scene: 场景/环境/日夜必须与描述相符,不符=> SCENE_MISMATCH
- subject: 主体缺席或被完全遮挡或不是画面主体 => SUBJECT_MISMATCH
- action: 期望动作必须在帧内可见(开始、进行中或完成态都算,但静止图不算) => ACTION_MISMATCH
- camera: 景别悬着(特写/近/中/全)与机位运动均须与描述一致,无法判断= false
- objects.missing/extra: 只登记明确要求/明确不该出现的;模型可证伪的才写
- verify:verdict=pass 仅当以上全 ok 且 obvious_issues 为空或全部为"无伤大雅"
- evidence.t 用秒,最多列3 条;t 来自画面标注
```

English variant (同输出 schema，只用英文枚举)：

```text
[system] You are a professional film-quality reviewer...
[user] Script requirement (one shot):

Scene: bright morning, modern kitchen.
Subject: the female lead in a red dress, holding a mug.
Action: she turns and looks at the camera.
Camera: medium shot, slow push-in.
Text overlay (if any): "IBRAND NAME]".

Frames from the generated shot:
t=0.0 (frame), t=2.5 (frame), t=5.0 (frame)
Output JSON:
{
  "scene": {"ok": true, "note": "..."},
  "subject": {...}, "action": {...}, "camera": {...},
  "objects": {"ok": true, "missing": [], "extra": []},
  "text_overlay": {"ok": true, "expected": "IBRAND NAME]"},
  "obvious_issues": [],
  "verdict": "pass",
  "fix_reasons": [],
  "evidence": [{"t": 2.5, "what": "camera pushes in towards lead"}]
}
```

### B2：关键镜头存在性定位（KEY_SHOT_MISSING 专用，绝对定位）

```text
# system
你是检测员。下面是一段"必须出现的关键镜头"的要求 + 成片按固定节奏抽出的帧（每帧都带绝对时间 t）。
关键镜头定义为: 必须在成片中出现的镜头，独立于整体剧情。
# 中文模板（输出 JSON 只此一个）
{
  "present": true,
  "t_center": 12.4,      // 该关键内容最像出现的中心时间（秒）
  "t_first_evidence": 10.0,
  "t_last_evidence": 14.8,
  "confidence": 0.93,    // 0~1
  "note": "在 10.0-14.8s 可见：主角正面（带品牌标特写）"
}
判定规则:
- 只有画面中确实出现"要求的主体+要求的动作全要素"才能 present=true；只有画面或只有动作不能成立
- 若证据跨多帧, t_first/t_last 按成片时间轴的区间给；无证据 => present=false, confidence=0.9以上
- 对这些 hard 镜头, 永远输出 JSON, 不要拒绝作答
```

给小模型降难度：把关键镜头拆成 2-3 个原子问题（"产品特写出现？""品牌名可见？"）各发一次，用逻辑与聚合。

### B3：成片级缺失/顺序检查（ORDER_DROPPED / 序列重排）

```text
# system
你手上有 (a) 全片分镜清单（每镜编号+一句内容摘要），(b) 成片被镜头边界切成 N 段的抽帧（每段首/末帧带时间）。
请判断：哪些分镜有对应画面段、哪些缺失、实际顺序与分镜顺序是否一致。
{
  "present_shots": [1,2,4,5],
  "missing_shots": [3],
  "sequence_ok": false,
  "sequence_notes": ["3(特写)出现于 2 之前"],
  "suspects": [{"shot": 3, "reason": "未找到对应画面"}]
}
提示：长片一次放不下时，按 chunk 分片处理再拼接；大量片段用二部匹配（cost=内容相似度）能比硬拼更稳。
```

### B4：台词-画面/唇型 检查（与确定性层配合）

- 确定性层先做：视频抽音轨 → ASR（whisper 中文）得到台词与时间轴 ↔ 分镜台词表做序列对齐（如 difflib）→ 算出每句"字幕/台词应有的出现窗口" vs "ASR 实际窗口"的偏移。
- 再上 VLM 判定画面动作是否对应："画面 t→t+w 期间‘举杯’这个动作是否在帧中出现？"（复用 B1 的 action 检查，feed 判定由台词驱动的事件词）。
- 唇型：跑 `syncnet_python`（模型官方开源，BMVC 2016"Out of Time: Automated Lip Sync in the Wild"）对含说话人脸片段算 audio-visual offset 与置信度。**若 |offset| 超过 2 视频帧（30fps 下 ≈66ms）或置信度低于模型阈值，标 LIP_ASYNC**。若镜中无清晰人脸/无音频，LIP 维度直接跳过并记 UNVERIFIABLE。

## C. 允许误差量 Δ 的建议（时间轴对齐容忍度）

| 对齐对象 | 推荐容忍 | 依据/来源 |
|---|---|---|
| 关键镜头出现时刻 vs 剧本预期时刻 | **Δ = max(0.75 × 该镜计划时长, 2.5s)**；命中判据 = 时间 IoU ≥ 0.5（出现窗口 ∩ 预期窗口）/预期窗口；0.3 ≤ tIoU < 0.5 记为"偏移警告" | 无权威数值；**落在 moment-retrieval 评估惯例（tIoU@0.5/0.7 为命中）** 的可迁移做法。短镜（<3s）必须用乘数（0.75×）否则固定 Δ 会大于整镜 |
| 台词/旁白与画面动作 | ±0.5s（中线）；>1s 记为果断 | 常见字幕/配音工具工程默认；**未找到可引用权威规范**（SMPTE 无公开该值），请按自己数据二次标定 |
| 台词文本与画面动作相符 | 不做时间差，只做"事件词 tmp 窗口" | 事件词在 ASR 时间戳 ±0.75s 的帧窗口内检查画面是否出现对应动作（建议值，同上无权威） |
| lip-sync | \|offset\| ≤ 2 视频帧（66ms@30fps） 且 置信度达标 | syncnet 官方评估口径即"offset 在 ±2 frames 内判正确"（BMVC'16 论文检验设置） |
| 模板一致：全片首次关键镜头若整体晚于剧本期望 >1.5Δ | 判 `KEY_SHOT_TIMING_FAIL`（MED~HIGH 结合该镜性质） | 同上 Δ 建议 |

另外两个给出工程建议：
- Δ 随镜长 自适应（上表第一个）优于常数型，避免"3 秒镜被 4 秒公差整个覆盖"的假阳性；
- 用 多模型半滑窗（VLM 每次只答一个窗口是否含关键物）+ 峰合（概率峰在 Δ 内即命中）替代"一刀切给一个时刻"，因为 VLM 对"在 t 秒"的精确点预测不可靠，对"哪个区域有"是稳定可靠的。

## D. 现成开源工具/论文名单（可直接搬什么）

### D1. 评测框架（按搬运价值排序）

| 仓库 | 链接 | 直接搬什么 | 备注 |
|---|---|---|---|
| **VBench** | https://github.com/Vchitect/VBench (CVPR2024, arXiv:2311.09182) | 16 维度代码全套；其中 6 项可对任意自定义视频跑：`subject_consistency`(DINO 帧对余弦)、`background_consistency`(CLIP)、`temporal_flickering`(MAE)、`motion_smoothness`(AMT)、`dynamic_degree`(RAFT)、aesthetic/imaging；其余对齐维度需其内置 prompt 套件 | **局限**：每个维度只报一个 0-1 均值/单号；**只能告诉你"平均像不像"，不告诉你哪镜错、错在哪个字段**；且只在整段视频上算，无"逐镜切片"概念 |
| **EvalCrafter** | https://github.com/EvalCrafter/EvalCrafter (CVPR 2024) | 17 个客观指标：文本对齐（CLIP-base）、语言 BERT、动作 VideoMAE-16、人像身份 deepface、文字 OCR（PaddleOCR 封装）、视觉质量 DOVER，`eval_from_metrics.py` 聚合输出榜单格式 | 优点：各指标独立成文件、现成可拆；缺点：同 VBench——整体打分，无逐镜 |
| **T2VScore** | https://github.com/showlab/T2VScore (arXiv:2401.07781) | **gT2VS（全局 CLIP 相似度）+ aV2VS（VLM 细粒度文本-视频对齐打分）的「文本对齐」双分数**；它的 aV2VS 思路 = 你的「VLM 把文本拆点逐点对画面」，可作为 B 模板的原始来源 | 开放代码不完整（dataset 在 HF），但论文的评分协议、金标准（TVGE 数据集）可引导自家裁判标注 |
| **VQ-Insight** | arXiv:2506.18564（已核实） | VLM 作视频质量裁判：多维度打分 + 时序建模 reward，思路可借鉴"训练自己的裁判 VLM"路线 | 无公开代码（截至调研日），仅用其思想 |
| **SemComp-Bench** | arXiv:2608.17426 | **VLM 结构化对问判断「任务结果是否完成」的协议（OA/GR），与你的「落版/品牌特写必须出现」指令完全同构**：把每个必须要求拆成 VLM 二分问题，聚合出失败码 | 数据是"参考图+指令→结果视频"，协议框架可直接改造成"分镜指令→成片镜" |

### 数据集/任务（教你怎么造"逐镜回对"的验证集与词表）

| 项目 | 位置 | 用处 |

## 6. 落地方案的推荐架构（把上面变成一条可跑管道）

```
┌─ 确定性层（先跑，便宜，且 pi 分钟级）──────────────┐
│ 1. 镜头边界(场景分割) → 每段 = 分镜候选对应段        │
│ 2. 每段抽帧（首/中/末 + 每1.5s，≤8帧）+ 时间戳      │
│ 3. CLIP(段均值) 对齐整段分镜文本 → 粗对齐/分段     │
│ 4. GRiT 目标检测: expected/missing/extra 物体       │
│ 5. OCR 落款/字幕；6. ASR 台词 vs 字幕台词对齐        │
│ 7. SyncNet 唇音（该镜头有人说话时）                  │
├──────────────────────────────────────────────────┤
│ 设备层：对着 B 模板逐镜发一次 VLM(agnes-3.0-flash) │
│   - 普通镜：B1 模板 → verdict pass/fix               │
│   - 关键镜：B2 模板（绝对定位，必达）                │
│   - 全片：B3 模板（缺失/顺序）+ KEY_SHOT 聚合        │
├──────────────────────────────────────────────────┤
│ 决策表：                                              │
│  BLOCKER 出现 → 该镜/整条全短路重做                  │
│  pass 且 fix 阈值内 → 人体复核                       │
│  置信度（VLM say NON）→ 人工抽检                    │
│  全量日志: 失败码、证据帧、VLM 原始 JSON 归档        │
└──────────────────────────────────────────────────┘
```

落地注意点：
1. **v:Vm 并行边界**：确定性层结果（物体列表、OCR、ASR 时间轴）打包进 VLM 提示（例如 accepted objects 提示），减少 VLM 编造；
2. **给 B 模板提供统一负面 class 词表**——不写出来，VLM 会给出它自己的差评词，你的失败码无法聚合；
3. **抽样帧必须带 t**，且关键镜检查必须覆盖整个区间（不是只有首末帧），否则"落版在 8s 出现"这种镜头会被漏；
4. 得意地把 2-3 个 VLM 候选并判（比如 agnes-3.0-flash 两次判 + 确定性客观维度），分歧才触发人工——照你已有 "slides 多 VLM 投票" 的机制复用；
5. 先用 20~40 支人工标过的镜做军官小组标校准 prompt 与 β参数（以「VLM 判定 vs 人工判定」一致率 ≥ 0.9 为过线）再上正式。
