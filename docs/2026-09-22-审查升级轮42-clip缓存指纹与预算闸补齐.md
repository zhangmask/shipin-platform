# 审查升级轮 42（2026-09-22）：clip 缓存输入指纹 + 预算闸补齐（七审）

## 42a：generate 的 clip 缓存脱钩（轮 29 的同类问题，generate 侧漏修）

`run_generate_phase` 的缓存捷径 `if mrec.get("qc") == "ok": continue`
只看 manifest 里的 qc 布尔——storyboard 改写（`/rewrite`，只 reset 阶段
不动 manifest 的 qc）或变体改风格后，vid prompt 重新派生并通过重审
（钱花了），循环到这里旧 clip 原样复用：**新 prompt 从未执行，旧视频
冒充新意图的产物入拼**，唯一兜底是 assemble 的 VLM 终审（软提示，
钱已花完才炸）。轮 29 修了 prompt 阶段（`_prompt_stage_stale`）、轮 26
修了 TTS（`_tts_text_sha`），clip 侧三者皆无。

**修**：`_clip_input_sha(vid_prompt, first_frame, last_frame, dur)`
输入指纹；缓存命中需同时满足 qc=="ok"、指纹匹配、clip 文件真实存在
（旧代码信 manifest 不验盘）；生成成功后记 `clip_input_sha` 入
manifest。输入不变的项目缓存行为不变（E2E 不受影响）。

## 42b：预算闸从"进门费"补成"进门费 + 阶段内熔断 + 全车道覆盖”

七审三条：

1. **两条车道无闸**：`/api/variant/{id}/run` 直接调
   `run_variant_phases`、`/api/tasks/{id}/retry` 重放的 fn 直接跑
   generate——都不查 `_enforce_budget`。修：两个端点补闸（variant_id
   即 project_id；retry 只对 generate/assemble/all 类任务生效）。
2. **阶段中无复查**：attempt 循环内不查预算，默认价下单次 generate
   可超支一个数量级（8 镜 ×3 attempt ≈ $1.44 vs $0.05 上限），下次
   调用才被 422。修：`_budget_exceeded(project_id)`（与
   `_enforce_budget` 同源：budget.json + cost_summary），每次
   `generate_video_agnes` 前复查，超限即返回 ok:False 并指明恢复路径；
   熔断自身异常不阻断（入口闸已拦过一轮）。
3. **LLM 花费零入账**：text 阶段每阶段最多 6 轮 ×（生成/修复/审片）
   的付费调用完全不在账内，预算只覆盖媒体生成。修：pricing 增加
   `llm` 档（$0.002/次估算，providers.json 可覆盖），5 个 LLM 调用点
   （剧本生成/修复、分镜生成/修复、阶段审片）逐一入账。

## 测试（intent 39/39、hardening 113/113）

- `_clip_input_sha`：同输入同指纹；prompt/首帧/时长任一变化即失配
  （4 例）；
- `_budget_exceeded`：无预算文件/未超限不熔断、超限熔断且原因含
  "上限"；LLM 调用产生 `llm` 成本行；
- `/api/variant/{id}/run` 超预算 → 422 且 detail 含"预算"。
