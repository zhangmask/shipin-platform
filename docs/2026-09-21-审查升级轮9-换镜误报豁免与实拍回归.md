# 审查升级轮9：VLM 断帧 kind 分类 + 边界豁免 + 凭据/审计加固（2026-09-21）

## 背景：轮8 实测暴露的两类问题

轮8 对 coffee-v7 成片终验抓到 11 处问题并正确挡下发布（verdict=fix）。
但 VLM 断帧层存在结构性误报与一次真实事故：

1. **正当换镜被报成 critical**（2/5 条断帧是合法分镜转场）——模型把
   「S02→S03 街角→门店」「S08 logo→S09 落版」这类*剧本上就该有的剪辑点*
   描述成「画面突变」。轮8 只是人工核对后放行，审核门本身不严谨。
2. **凭据被断帧串覆盖（事故）**——批次解析里 'boundary' 豁免分支用
   `key = f"{t}|{desc}"` 去重，**把外层 AGNES 凭据变量覆写成了 VLM 返回
   的断帧文本**；下一批次请求的 `Authorization: Bearer 11.09|画面从
   咖啡店门口…` 触发 http.client latin-1 UnicodeEncodeError（非 ASCII
   进头直接崩）。表现为「第一批请求正常、第二批开始坏 key」的诡异时序。

## 改动

### 1. 断帧结果模型带 kind 分类（hard_gates `_batch_prompt`）
- `breaks` 从字符串数组升级为 `{t, desc, kind}`；kind ∈ `intra|boundary`。
- 提示词明示：*同一分镜内部*的突变/崩坏/闪帧才算异常（intra），
  *相邻分镜交界*的正常切换（t 落在分镜表镜头边界附近）必须标
  boundary 且不得列入异常。

### 2. 边界豁免门（`vlm_review_final`）
- `_shot_boundaries()` 由 storyboard 累计时长算真实边界；
- `kind=boundary` 且 `|t - 最近边界| ≤ 2.0s`（采样帧错位 0.45~1.6s，
  短镜跨边界成对帧可达 ~1.6s，取 2.0 才覆盖）→ 移入
  `boundary_transitions` 列表（计 reason 不计 findings）；
- `kind=boundary` 但远离任何真实边界（模型乱标）→ 仍按 critical 拦截；
- 旧字符串断句（无 kind）保持原语义：全部 critical（向后兼容）。

### 3. 凭据加固
- `_key_ok()`（hard_gates + llm_review 同形）：仅可打印 ASCII 且
  ≥16 字符才认 key；
- `_ask_vlm` 发送前校验，坏 key 抛可读 ValueError 而非 latin-1 崩溃；
- **修掉覆写 key 的根因**：豁免分支去重变量改名 `bkey`，不再触碰外层
  `key`（AGNES 凭据）。
- `%TEMP%/agnes_key.txt` 兜底保留但同样过 `_key_ok`（外部进程写过
  模型输出文本时自动拒用）。

### 4. VLM 请求重试
`_ask_vlm` 对 ≥500 / 连接类异常重试 3 次、退避 3s（实测上游偶发 500；
一次瞬态错误不该毁掉整场终验，失败仍如实上抛）。

### 5. assemble 路径 G5 审计 bug 修复（pipeline_runner）
G5「clip 哈希一致性」审计块引用 `sids` 时该变量尚未定义 → 在引用前
计算（variants E2E 真实成片因 UnboundLocalError 中断）。
