# 审查升级轮 23（2026-09-22）：assemble 响应通道级结论汇总

## 问题：终审 fix 不可定位

轮 12-22 建起了多通道审查（clip 单镜诊断、关键帧审图、入拼复审、
旁白/台词声轨、黑帧……），critical 全部并入终审强制 fix——但
assemble 响应只给 `final_review.verdict` + reason「按 findings 修复」。
运营拿到 fix 后要自己去项目目录翻 `shots_review.json` /
`parts_review.json` / `keyframes_check.json` / `narration_check.json`
四五个文件才知道**哪一镜的哪个通道**出的问题。用户原话「审核到底
有没有反馈」——反馈不可定位等于没有反馈。

## 改动（pipeline_runner.py）

assemble 返回新增 `review_channels`：按通道逐镜列出
`{channel, shot_id, verdict, critical}`：

- `shot_review`：每镜 clip 单镜诊断（轮 12）；
- `keyframe`：每镜关键帧审图（轮 21，`__keyframe_<sid>__` 键）；
- `part_review`：master 补料入拼片段复审（轮 13，带 part_idx）；
- `narration`：全片旁白/台词声轨存在性（轮 14/20）。

明细仍在各 `*_review.json` / `*_check.json`，汇总是定位入口。

## 验证

- 用 coffee-v7 真机产物（v12 逐镜诊断 + v14 旁白检查 + v21 关键帧）
  干跑汇总逻辑：10 镜 shot_review 中 S07 `fix/critical=1` 一眼定位
  （其余 pass），keyframe/narration 通道 ok；
- E2E 新增断言：assemble 响应必含 `review_channels` 且每项有
  channel/critical 字段（真实走通生成+装配后校验）。

## 示例（真机数据）

```
{'channel': 'shot_review', 'shot_id': 'S07', 'verdict': 'fix', 'critical': 1}
{'channel': 'keyframe',    'shot_id': 'S01', 'verdict': 'ok',  'critical': 0}
{'channel': 'narration',   'verdict': 'ok', 'critical': 0}
```
