# 审查升级轮 33（2026-09-22）：发布物三方哈希比对（终审凭证绑定被审视频）

## 缺口（三审审计的共同根因）

三轮审计收敛到同一个根因：**finalize 是纯状态位检查，发布物本身
（字节）从未被任何一道门在发布时刻重新核对过**。已实证的绕过路径：

1. **assemble 跑通一次 → `/api/video/mux` 换个文件 → finalize**（3 个
   调用、零故障注入）：mux/normalize 带 project_id 即把新文件记成
   post_production PASS，而 final_review.json 还是旧视频的 pass；
2. 直接换盘上 `final.mp4` 再 finalize（连 mux 都不用了）；
3. 轮 30 的手工链路凭证可对**任意视频**签发（endpoint 无 project 目录
   约束）：对 preview cut 跑终验带 project_id → pass 凭证落给从未被审
   的成片；
4. 已发布项目（RELEASED）成片被换后，轮 32c 的幂等路径给假确认。

轮 25/27/30 的全部内容门（VLM 断帧/品牌/时间轴/旁白/单镜/入拼/字幕
验收）在发布入口被整体绕过。

## 改动（hard_gates.py + api.py + pipeline_runner.py）

**凭证绑定**：`vlm_review_final` 返回新增 `video_sha256`（被审视频的
内容哈希）——终审凭证从此记录「审的是哪条视频」，assemble 与手工链路
两条写入路径自动带上（`_save`/端点落盘的都是同一返回体）。

**路径约束**：`/api/review/final-video` 带 project_id 时，被审
`video_path` 必须解析在项目目录内，否则返回 blocked——拒绝对外部/
他项目视频签发本项目凭证。

**finalize 三方哈希比对**（verdict 闸之后、发布之前）：

```
盘上 final.mp4 sha256  ↔  final_review.json.video_sha256（审的那条）
                       ↔  post_production.artifact_hash（混音归一后记的那条）
```

- final.mp4 缺失 → `final_artifact MISSING` 409；
- 与终审凭证记录的被审视频不一致 → `REVIEW_VIDEO_MISMATCH` 409
  （成片在过审后被换过）；
- 与 post_production 指纹不一致 → `ARTIFACT_MISMATCH` 409；
- 任一侧哈希缺失（旧数据/未记）时跳过该侧比对，不误伤现存项目。

**幂等不免检**（轮 32c 的加固）：已 RELEASED 项目重复 finalize 时，
仍先核对成片哈希与凭证一致才返回 200；不一致落到完整门给 409。

## 33c 附带（三审审计 #4/#5）

- **台词删除残洞**：台词被删/置空的镜，manifest 是累积加载的，旧
  `dlg` 路径不显式摘掉就会留在 assemble 的声音设计里（旧台词轨照播）、
  align 按旧音频算窗口，而新指纹让该镜永远「新鲜」——无门能发现。
  修：重合成过的镜若当前无台词文本，`manifest[...].pop("dlg")`；
- **成本只计成功段**：`record_cost` 移到失败检查之后、按成功段计数
  （旧代码失败也记全量 units，账目虚高、可能提前误闸预算）；
- **`_save` OSError 不再裸 500**：`_iterate` 落盘失败返回
  `decision=stop` 的可消费结构（reason 指名 IO 问题），同步端点得到
  ok:False+reason 而非 500，异步任务不整轮重试烧钱。

## 测试（TestApiGates，101/101 in suite）

新增 5 例：过审后换 final.mp4 → 409（REVIEW/ARTIFACT MISMATCH）；
三方哈希一致 → 200；有凭证无成片 → 409 MISSING；endpoint 拒绝对项目
目录外视频签发凭证；`_write_final_review` helper 升级为连 final.mp4
一起落（与 post_production 指纹同内容），`_fresh_project_dir` 清目录
隔离上一次运行的残留（API 测试写真实 data/projects，残影会污染断言）。
