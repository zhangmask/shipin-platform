# 审查升级轮 26（2026-09-22）：TTS 复用改文本指纹判定 + 旁白 glob 吞台词文件

> 同轮 25：独立子智能体审计发现，本地逐行复现实锤。

## 26a：改了台词，说的还是旧词

TTS 复用判定是「项目目录里有没有 `{sid}_*.mp3`」——纯文件名。
`/api/review/iterate`（api.py:833-861）与 `/api/pipeline/{id}/rewrite`
改了 storyboard/script 的 narration/dialogue（shot_id 不变）后重跑
generate：旧 mp3 还在 → 直接复用；同时 `mrec["qc"]=="ok"` 缓存让旧
clip 也不重生不重审。**成片口播是旧词、字幕（按当前 storyboard 烧录）
是新词**——声画不一致、直接违反剧本，而全链路没有任何门能发现
（旁白存在性门只查静音；终审 VLM 转写字幕但不与剧本比对）。

**修复**：`_tts_text_sha(shot)` = sha256( narration \x00 dialogue_text )
前 16 位；manifest 每镜记 `tts_text_sha`；复用判定 `_tts_fresh` 从
「有文件」升级为「文件在 **且** 文本指纹匹配」——指纹不符 → 该镜进
`need` 重新合成（新旧文件并存，glob 按 mtime 取新）。

## 26b：旁白轨会取到台词音频

`glob_tts(work, sid)` 的通配是 `{sid}_*.mp3`，而台词段的输出文件名是
`{sid}_dlg_<uuid>.mp3`（tts_service.build_segment 用 segment.shot_id
命名）——**台词文件被旁白 glob 吞掉**，mtime 最新者胜。台词通常在
旁白之后合成（台词先入队、旁白跟后？实际两段同批合成，顺序不定），
一旦台词文件更新，`_tts_of` 就把**台词音频当旁白轨**交给
`align_narration` 算时长——旁白窗口按错音频对齐，成片声画错配，
同样无门能发现。

**修复**：`glob_tts` 对非 `_dlg` 查询排除 `{sid}_dlg*` 文件名。

## 测试（TestTtsReuse，3/3）

- glob 排除：`S01_*.mp3`（旧）与 `S01_dlg_*.mp3`（新）并存 →
  `glob_tts(work,"S01")` 必须返回旁白文件而非更新的台词文件；
- 文本指纹：同文本同哈希；旁白变/台词变哈希必须变；
- 失效语义：manifest 旧指纹 ≠ 当前文本哈希 → 不可复用（走重生）。
