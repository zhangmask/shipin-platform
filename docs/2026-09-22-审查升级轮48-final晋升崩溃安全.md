# 轮48：final 晋升序列崩溃安全（八审 P4 遗留项收口）

日期：2026-09-23。承接轮47 审计遗留清单第一项。

## 问题

轮43 的 assemble 重入保护把 mux/normalize 改成 candidate 中间产物，
但**晋升序列本身有崩溃空窗**：

```
旧序列:  final.mp4 ──replace──▶ final.published.mp4   # 旧片被 move 走
         final_norm.candidate ──replace──▶ final.mp4  # 新片上岗
```

两步之间崩溃（磁盘满/进程被杀/OSError）→ **盘上没有任何 final.mp4**。
此时 finalize 四道门只能 fail-closed 报 MISSING（不误放行，这一点
是对的），但轮43 注释许诺的「保留上一版可回滚」没有任何恢复路径——
`final.published.mp4` 全库只有 3 处赋值、零读取方，是空头支票。

## 修复（pipeline_runner.py）

1. **晋升序列改「先拷贝备份 → 原子替换」**（提取为 `_promote_final`
   可单测）：旧片 copy2 成 final.published.mp4（**旧片仍在上岗**），
   再 os.replace 原子晋升——任何时刻盘上都有一个完整文件，move 空窗
   消除。备份失败（磁盘错）不阻断晋升（保留旧 try/except 语义）。
2. **`_recover_final(work)` 残局恢复**：assemble 入口检测
   「final.mp4 缺失 + final.published.mp4 存在」→ 拷回上一版上岗，
   本次重跑随后用新 candidate 正常替换它。恢复动作记进 assemble
   响应 `out["final_recovered"]`，对运营可见。
3. 晋升失败（候选缺失/哈希读不到）显式返回 assemble 失败，旧片
   原封不动。

## 测试（TestFinalPromotion，7 例）

首次晋升无备份 / 二次晋升备份内容正确且旧片留岗（拷贝非 move）/
候选缺失显式失败且旧片不动 / 恢复残局 / final 在岗时恢复 no-op /
无残局 no-op / 拷贝失败不炸（尽力而为，不变成崩溃源）。
