# shipin-platform 借鉴 hypit 优化方案

> 编写日期:2026-09-17
> 被借鉴项目:[hypit-ai/hypit](https://github.com/hypit-ai/hypit)(6160★,Apache-2.0 with conditions,TS monorepo,pnpm/Node22)
> 思路:不是搬运 TS 代码,而是把 hypit 已验证的**架构决策与交互范式**翻译成我们 Python 平台的确定性落地。
> 每个借鉴点都标注来源(hypit 的具体包/文件)与本平台的落点。

---

## 0. 一句话评估

hypit 证明了"给 Agent 一个**可复用、可重跑、可参数化**的视频工作流源,而不是一次性 prompt"这件事是成立的:
- 参考视频 → Agent 拆解成 `*.svml`(结构化源)+ `*.svs`(样式表)+ `*.svrun`(运行目标);
- 一次生成,之后换素材/换词/换风格只是**改源再跑**,且全程记录成本;
- 组件/Provider/Endpoint/凭据四层分离,模型服务可插拔。

这与我们 DELIVERY 方案("ComfyUI 式一键成片")方向一致,恰好补齐了我们方案里标注为**断点**的四块:
输入侧归一化、品类模板注册表、供应商抽象、一次成片多变体。

**不搬的东西**(技术栈错位,搬了是负债):
- TS 本体、SVML 解析器、超帧浏览器渲染(64 个 headless Chrome 逐帧渲染 HTML)→ 与我们的 FFmpeg 确定性管线不是一个成本量级;我们保留 FFmpeg 链路。
- 组件包/插件系统(80+ packages 的生态)——我们用"模板注册表 + 配方"的轻量等价物。

## 1. 借鉴点清单(按优先级)

### P1-① 供应商抽象层:Model / Provider / Endpoint / Credential 四层分离

**来源(hypit)**:
- `packages/runtime`(catalog/credentials/endpoints)——Runtime Profile JSON 声明:
  ```json
  {
    "format": "hypit.runtime-local@1",
    "dataRoot": ".hypit/runtimes/local",
    "credentials": {},
    "endpoints": {
      "media.local": { "use": "@hypit/provider-media-local" }
    },
    "bindings": {}
  }
  ```
- `packages/credential-store-env` —— 凭据只存环境变量,Profile 只放"引用名",绝不写入密钥
- `packages/provider-*` —— 单一 Provider 包负责把"需求"映射到"具体服务 API",切换服务不碰上层代码

**落点(我们)**:
- 新增 `config/providers.json`(等同 runtime profile):
  ```json
  {
    "profile": "shipin.default@1",
    "credentials": {"agnes": {"env": "AGNES_KEY"}, "openai": {"env": "OPENAI_API_KEY"}},
    "endpoints": {
      "image.default":  {"use": "agnes-ai",      "model": "agnes-image-2.5-flash"},
      "video.default":  {"use": "agnes-ai",      "model": "agnes-video-v2.0", "resolution": "720p"},
      "tts.default":    {"use": "agnes-ai",      "model": "tts-v1"},
      "asr.default":    {"use": "whisper-local", "model": "medium"}
    },
    "bindings": {}
  }
  ```
- 新增 `src/shipin_platform/services/provider_registry.py`:
  - `resolve(capability)` → `(endpoint, creds)`;凭据只在调用时按 `credentials.<name>.env` 解析(继承 generate_assets.py 里"调用时读 env"的历史教训);
  - 未注册函数/未配置凭据 → 稳定错误码,绝不静默降级(对齐 hypit「请求失败不会偷偷换账户」)。
- 改造 `generate_assets.py`:`generate_image_agnes / generate_video_agnes` 保持公开签名,内部改走 registry;`_safe_fetch` 保留并作为所有 http 出口的统一入口。
- **安全**:所有出网请求仅允许 http/https;请求前校验 host;拒绝 localhost/环回/私有/保留地址(已有 `_safe_fetch` 白名单+IP 校验,这次把它收编成 registry 的统一安全网关)。

**交付物**:`config/providers.json`、`provider_registry.py`、`tests/test_provider_registry.py`(含安全用例)。

### P1-② 参考视频理解 → 输入归一(模仿 hyp 的 "reference clone")

**来源 (hypit)**:
- `skills/hypit/references/creation/reference-video.md` —— 对参考视频做"纵深回读":抽帧网格 + 字幕链接 + 节奏/画面系统解析,产出 Analysis(整体解释)+ Timeline(带时间细节),再凝练成结构
- 这就是他们"clone any video"的第一步:把视频变成结构化报告,而不是让 Agent 自由看一一眼。

** 落点**:
- 在我们三入口(意图快启/文档启动/参考对齐)的 **C 入口** 实现落地:
  `POST /api/ingest/reference` 接收参考视频 → ffmpeg 抽帧 + whisper 出词级时间戳 + 规则抽取(场景数/时长/镜头节奏/旁白密度/黑切统计)→ 输出 `reference_report.json`,映射成 brief 约束(9 维度预填)。
- 与我们现有 `review/slideshow_risk.py`、`ffmpeg_engine` 复用,不新增依赖。

**交付**:`src/shipin_platform/analysis/reference_profiler.py` + `tests/test_reference_profiler.py`。

### 1-③ 词级时间对齐 → 卡拉 OK 字幕 + 锚点插入(WhisperX 词级对齐)

**来源 (hypit)**:
- `packages/whisperx` ——"词级时间回传以 Script 为单位";`caption` 组件的卡拉 OK 字幕:彩色词盒逐词点亮,与音频逐字同步(用 WhisperX 的 word-level evidence 驱动)
- 我们的 SRT 字幕是句子级,缺失"词与词的锚定"能力

**落点**:
- `whisper_service.py` 已开 `word_timestamps:true` 但只导出 JSON;本次把**单词语义词时间戳**结构化为 `word_anchors`(对齐到句/词),供:
  (a) 字幕渲染升级:逐词高亮(ASS 卡拉OK效果);
  (b) 后续变体工作的「锚点」基础(改一行台词→时间轴自动重排,这是 hyp 的核心可变性卖点)。

**交付**:`subtitle_renderer.py` 增加 `karaoke: true` 选项(词级 ASS)+ 测试。

### 2-① 变体/重拍:一次制作、多次变体(swap-host / swap-topic)

**来源 (hypit)**:
- `examples/ranking-football/swap-host.svml`、`swap-topic.svml`、`swap-effect.svml`、`variants.md` —— 同一份 SVML 换 presenter/topic/UI 素材 = 3 个变体,一个参考视频出 N 条;成本每条约 $1.1
- 我们 coffee-v7 只能一单一切片,没有"同一结构换词换角色"的能力

**落点**: 新增 `POST /api/pipeline/variant`:给定 base project + variant 参数(替换 brief 字段、替换主角描述、替换旁的台词),复用基准素材,只重新生成变化镜头 → 输出第二个 project(结构克隆、素材复用清单输出)。

**交付**:`orchestration/variant_runner.py`(复用 pipeline_runner 资产) + 测试。这是三期交付中最大头,排 P2。

### 2-② 时长估算与节奏保真(estimate 包)

**来源 (hypit)**:
- `packages/estimate/README.md` —— "中文按每个汉字≈1 音节,5.25 音节/s(normal)";让作者在写文案时就算出预估时长,不依赖已有 TTS 返回
- 我们 SCRIPT_PROMPT 里硬编码总字数≈时长×2.7 —— 只适配了 TVC

**落点**: `review/hard_gates.py`(或新 `estimate.py`)实现 `estimate_speech_sec(text, lang=zh/en)`,按语言密度表(含配音速率 ramps)输出保守区间,替换硬编码系数;作为审查门 的辅助证据。

**交付**:`estimate.py` + 单测(中文/英文/嵌入英文名)。

### 3 远期(今日城主不落地,记录方向)
- **SVS 样式表等价物**:把 SCRIPT_PROMPT/STORYBOARD_PROMPT 的审美/结构常量抽成 `templates/<category>.yaml`(短剧/教程/宣传片)——即 DELIVERY 里的"品类模板注册表",hyp 的 SVS 给了我们字段组织参考
- **组件化**:把「字幕」「落版卡 kenburns」「角标」等我们每个镜头重复的小行为, 从代码常量升为幂等组件参数(配方),给变体复用

## 3. 安全与边界(对齐 Mimosa 约束)

- 任何服务端发出的外部 URL 请求:仅允许 `http/https`;请求前校验 host;并拒绝
  localhost / 环回 / 私有 / 保留地址。
- 统一走 `provider_registry` 的安全网关,不再散落各处 `urllib` 直连(收编 `_safe_fetch`)。
- 凭据不写入任何 JSON/日志;只以环境变量引用(`credentials.<name>.env`)。
