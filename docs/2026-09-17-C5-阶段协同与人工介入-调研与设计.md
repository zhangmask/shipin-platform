## 2. 对照提炼（哪些吸收 / 哪些不收）

**吸收（且与"确定性服务端 + API 生图"兼容）**：

1. **执行留痕即前端**（n8n/Dify/Flowise）：平台不"生成前端"，而是**每次阶段动作落一条结构化事件**（谁调用/什么阶段/产物引用/结果），前端 5s 轮询事件流呈现 → AI 用 MCP 调度函数时，前端自然长出"这轮 AI 干了什么"。→ 落点：`pipeline_events` 表 + store 自动埋点 + `GET /api/pipeline/{id}/events`。
2. **中间产物可见**（Airflow 任务产物 / ComfyUI 节点输出预览）：script/storyboard/image_prompt/video_prompt/final_review 全部给 GET 端点；final.mp4 抽 3 帧作预览图（ComfyUI 风格）。→ `GET /api/pipeline/{id}/artifact`、`GET /api/pipeline/{id}/preview`。
3. **人工改动后重跑**（Airflow 清态重跑 / ComfyUI 改 prompt 重排）：用户改写剧本/分镜 → 确认清空 + 下游自动失效（BLOCKED）→ 重新走网关与重跑。→ `POST /api/pipeline/{id}/rewrite`（只允许 script/storyboard；提示词阶段由分镜确定性派生，避免手改破坏对应关系）。
4. **预算闸**（windmill 审批前置 / n8n 执行权限；结合《对比报告》ViMax#37 成本失控教训）：项目级 `max_budget_usd`，generate/assemble 入口硬校验，超限 422 直接拦住（查询成本与阈值不用猜）。→ `POST /api/pipeline/{id}/budget` + 两个阶段入口检查。
5. **开跑前检查**（Prefect/Argo 的 preflight 意识；MoneyPrinterTurbo preflight 机制——上轮《对比报告》§6 已列入差距）：`POST /api/pipeline/{id}/preflight` 静态检查（凭据、产物前置、预算、assets），不触发任何生成。

**不吸收**：React Flow/D&D 节点图（n8n/ComfyUI）；DAG 通用调度器（Airflow）；Agent 美化（Flowise/agent）；XML/Premiere 生态（auto-editor，上轮已定不碰）；这些在我们"固定 8 阶段状态机 + 确定性"模型下都是负债。

## 2. 设计（C5 动手点）

见下方代码注释与收口记录；核心 API 清单：

```
GET  /api/pipeline/{id}/events?limit=50      # 执行轨迹（AI 调用自动留痕）
GET  /api/pipeline/{id}/artifact?stage=script # 中间产物内容（exists/content）
POST /api/pipeline/{id}/rewrite               # {stage, content} 改写+清确认+失效下游
GET  /api/pipeline/{id}/preview               # assemble 后 3 帧预览
POST /api/pipeline/{id}/budget                # {max_budget_usd} 预算稳止（null=解除）
POST /api/pipeline/{id}/preflight             # 只读体检（凭据/产物/预算/闸门）
```

安全约束（延续 Mimosa）：所有端点为同源 REST、无外部 URL fetch；产物路径全白名单 + resolve 校验，杜绝穿越；预算波动只影响当前动作，不改历史。
