# 审查升级轮 31（2026-09-22）：TTS 合成失败路径修复（轮 26 指纹机制的漏洞）

## 缺口（新审计 #2：轮 26 自己的修复在失败路径上被绕过）

轮 26 把 TTS 复用改成文本指纹判定，但**指纹重盖逻辑假设「合成了就一定
写出了新文件」**——而 `synthesize_segments_sync` 的失败是静默的：
`asyncio.gather(..., return_exceptions=True)` 把异常挂到段上
（`seg.error` / `output_path=""`，tts_service.py:106-122），旧调用方
**直接丢弃返回值**（pipeline_runner.py:981）。

触发链：改了 narration → 指纹不符进 `need` 重合成 → edge-tts 失败
（网络/限流/5xx），而工作目录里有上一轮遗留的 `{sid}_*.mp3` →
`_tts_of` 的 glob 按 mtime 取到**旧音频** → 紧接着 line 990 无条件把
**新**指纹盖上去 → **该镜从此对指纹永远「新鲜」**，无限复用旧口播：
成片口播是旧词、字幕是新词（正是轮 26 要消灭的声画不一致），
`align_narration` 按旧音频算窗口，record_cost 照扣，且全链路没有门
能发现（终审 VLM 核画面/品牌，旁白门只查声轨存在性、不核文本）。

## 改动（pipeline_runner.py）

- 提取 `_tts_failures(segments)`：error 非空或 output_path 为空的段
  即失败段；
- generate 接收 `synthesize_segments_sync` 的返回，失败段非空 →
  **显式返回 ok:False**（reason 带失败段与前 3 条错误，注明「旧音频
  已作废，拒绝盖新指纹」）——与既有的「TTS 缺失」硬失败同构；
- 失败即返回意味着指纹不会被重盖 → 下一轮重跑该镜仍是 stale → 重新
  合成，不会卡死在旧音频上。

## 测试（TestTtsFailureDetection，2/25 in suite）

失败段（error 非空 / output_path 空）被检出；全成功段无失败。
