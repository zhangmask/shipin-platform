## 环境基线(真实使用前)

AGNES 探活:/v1/models 200、/v1/chat/completions 200(文本/VLM 车道通)、
/v1/videos 503(视频生成车道外部阻断)。子智能体因此覆盖了文本/审查/画布/
质检/发布/变体等全部车道,视频车道顺带验证了平台的降级与诊断。

## P0-1 generate 裸 500 零诊断(A-P0-1 + 服务端日志 7×500)

- 病:`SHIPIN_MEDIA_BACKEND=local` 下 h3api 不可达,`LocalMediaError` 从
  `generate_image_agnes` 裸抛到 FastAPI → 500 纯文本 "Internal Server Error":
  不带原始异常、无 attempts 诊断、崩溃早于任务注册与审计落账(失败对
  tasks/audit 双台账不可见),排障断裂。
- 修:`_media_error_result`(pipeline_runner)——LocalMediaError/429/503/
  其它分类转结构化 `{"ok": False, "code": MEDIA_BACKEND_UNREACHABLE|
  UPSTREAM_RATE_LIMITED|UPSTREAM_UNAVAILABLE|MEDIA_GENERATION_FAILED,
  "upstream_error": {...}, "next_action": ...}`,与视频 attempt 诊断
  (轮45)同范式;端点层 `_enqueue`/`pipeline_generate` 再兜底
  (ValueError→422、LocalMediaError→502)。

## P0-2 第三方 restore 把在跑项目打死且无恢复路径(A-P0-2)

- 病:`/api/pipeline/{id}/restore` 不在 agent-guide;detail 里 caller 记的是
  **版本创建者**而非本次回滚者;回滚后阶段 PENDING + 下游 BLOCKED,而响应
  只说「重新确认后再跑」——唯一恢复路径(重跑 pipeline/text 重建下游,要
  花钱、可能被预算挡)完全不可见,项目事实性死亡。另 invalidate 文案
  「失效下游 3 个阶段」与 detail 列 6 个不一致(rowcount vs 全下游名)。
- 修:restore 记真实 principal(caller=版本创建者 分开标注);响应加
  `next_action` 四步恢复路径(调预算→重跑 text→重新 confirm→generate,
  含跳过后果);invalidate 文案统一为「全部下游 N 个已置 BLOCKED(名单;
  其中 M 个原有状态被更新)」;agent-guide 补 restore 端点与破坏性警告、
  补 versions 端点、补 brief 是 pipeline/text 的第三道硬闸(文档缺口)。

## 画布车道 6 项(B-P1×2/P2×3/P3×2)

- **P1-1 tts 节点 100% 崩**:`create_tts_service(str, str)`  second 参传
  str,`TtsService._load_roles` 的 `.exists()` AttributeError(画布车道一直
  是坏的;pipeline/api 两调用方都传 Path)。修:engine 传 Path + TtsService
  `__init__` 内部包 Path(双保险,传 str 不再是要命形态)。
- **P1-2 未知节点类型 500**:`get_def` KeyError,api_graph 只捕 ValueError。
  修:422 + `UNKNOWN_NODE_TYPE`。
- **P2-3 PUT 节点缺 id 500**:`validate_graph`/`_cycle_members` 裸
  `n["id"]`。修:一律转可读 err(「节点 #N 缺少 id 字段」),边端点未注册
  类型也可读。
- **P2-4 run-all 假成功**:顶层恒 ok:true,只读 ok 的 agent 判全图成功。
  修:`ok = not failed` + `failed: []` 列表。
- **P2-5 下游无 skipped 语义**:上游失败后下游节点复述上游错误、无法区分
  「本节点失败」与「上游失败被跳过」。修:`_upstream_of` + skipped/
  upstream_failed 标记 + 事件;不执行直接标。
- **P2-6 results schema 不一致**:成功/失败条目键位不同。修:统一
  ok/state/blocked/skipped。
- **P3-7 asset 无扩展名恒 404**:docstring 承诺「im1 或 im1.png 均可」,
  但产物真实命名 `{node}.{ext}`(无下划线),轮55 的 `{stem}_*` 兜底 glob
  是死代码。修:`{stem}.*` + `{stem}_*` 双形态兼容。
- **P3-8 params repr 注入**:dict/list 被 Python repr 化静默注入提示词。
  修:`_param_text`——dict/list 走 JSON(ensure_ascii=False)。
- **P3-9 尾帧文案写「首帧」**:`last_prompt` 回退到 first 的模板。修:
  回退文本按端口各说各话。

## 质检/审核链(C-P1×2/P2×3)

- **C-P1-1 字幕 cue 超时长 → 404 + 内部 tmp 路径**:中点 -ss 越 EOF →
  ffmpeg 不产帧 → Image.open 裸抛 FileNotFoundError。修:verify 先探片长,
  越界 cue 标 `beyond_duration` + `measured:False`,check 转 critical
  violation(带 cue 序号/结束秒/片长);帧抽取失败也标记不泄内部路径。
- **C-P1-2 submit_task 检查-插入竞态**:2 线程同项目并发提交 3 轮 2 轮双
  202。修:`_submit_lock` 包住检查+插入(单进程部署假设已固化)。
- **C-P2-1 clip_qc 不落口径**:pipeline 落账只写 `{"attempts":...}`,丢
  checks/findings——历史 ok 行无法复现「当时按什么时长判的」。修:落账带
  verdict/checks/findings(attempts 保留)。
- **C-P2-2 final-video 目录输入**:`json.loads(...)["format"]["duration"]`
  裸 KeyError('format') → reason 里是天书。修:`_extract_frames` 文件+
  探测守卫,失败抛可读 RuntimeError。
- **C-P2-3 ingest 无音轨视频判 100% 语音**:silences=[] → ratio=1.0
  「dense_narration」→ brief_prefill 误判 talking_head。修:无音轨 →
  `speech_ratio=None/density="no_audio"`(不可推断),下游 `_tone_hint`/
  `build_brief_prefill`/summary 全部 None 安全。

## 测试环境修复(真实使用暴露的交叉污染)

- `.env`(本地 gitignored 配置)被配成 `SHIPIN_MEDIA_BACKEND=local`,而本机
  无本地 h3api 节点;api 模块导入时 `load_dotenv` 把它灌进进程环境 →
  **组合跑时后面导入的用例 TTS 全切本地模式报「h3api 不可达」**(单文件跑
  不导入 api 所以只有组合跑挂——顺序依赖污染)。修:.env 改回 auto +
  conftest `setdefault("SHIPIN_MEDIA_BACKEND", "auto")` 钉死(显式要测
  local 的用例仍可自行 setenv)。
