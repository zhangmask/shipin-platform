# 审查升级轮 36（2026-09-22）：引擎规则两修（机位比对归位/标点逃逸）

## 36a：机位相邻比对的索引错位（finding 挂错镜）

`_review_storyboard` 的机位雷同检查先把各镜 camera 收进**压缩缓存**
`_cam_cache`（跳过空 camera 字段的镜），却用缓存下标去索引**原 shots**：
camera=[static, "", static] 时缓存=["static","static"]，i=1 比较的是
两个 static（命中雷同），finding 却挂到 `shots[1]`——**一镜没有
camera 字段的镜**上。后果双份：修订计划让 LLM 去改一镜不存在的字段
（诱发 STALL 死循环），且真实的相邻对被错位比较（空 camera 镜两侧的
机位关系失真）。

**修**：显式 `(shot, camera)` 成对遍历（`zip(_cams, _cams[1:])`），
finding 的 evidence 指向真正持有该机位的相邻镜对；空 camera 的镜不
参与比对（不制造伪相邻）。

## 36b：重复旁白归一化逃逸（标点差异即放行）

旁白跨镜重复的 key 是 `re.sub(r"\s+", "", n)`——只去空白。「每一杯
都是匠心」vs「每一杯，都是匠心」只差一个逗号 → 两个不同 key → 放行，
配音照念两遍（注释自称"逐字重复即 critical"）。

**修**：`_norm_narration_key` = 剥离空白 + 中英文标点（CJK 全角、
ASCII punctuation、破折号/省略号/间隔号）+ lower；脚本与分镜两处
重复检查同用。

## 测试（test_engine.py，50/50）

- `[static,'',static]` → 雷同 finding 的 evidence 指向 S01/S03（真正
  持有 static 的相邻对），不再挂到无 camera 的 S02；
- `[dolly in,'',static]` → 无误报（空 camera 不参与配对）；
- 「每一杯都是匠心」vs「每一杯，都是匠心」→ NARRATION_DUPLICATED
  critical（旧行为放行）。
