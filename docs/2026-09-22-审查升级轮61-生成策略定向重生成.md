# 轮61：生成策略转向——定向重生成 + 首帧锚定图brew button特写（S03 判定为模型上限）

日期：2026-09-25。轮60 实证 prompt 层对「按键位置」到边际(S03 三重
约束仍侧面键),本轮换**生成策略**:generate 内定向重生成 + 首帧锚定
图特写,真链路重跑 tvc-07431 验证。

## 61a:generate 阶段定向重生成(pipeline_runner.py)

原范式:单镜 VLM 诊断(vlm_review_shot)critical 只记录,由 assemble
终审统一阻断——**发现太晚、代价太高**(素材已入拼,重跑整轮)。
轮61:diagnostic critical → 不 break,**立即换 attempt 1 的
「FIXED camera」变体重生成**;定向重试仍 critical 才落记录放行
(原 assemble 阻断范式不变)。

三个关键设计:
1. **阶梯 prompt 带硬约束**:attempt 1/2 的阶梯 prompt 原来用裸
   motion——定向重试会丢掉轮60 全部强化(景别/品牌/按键)。阶梯
   三档都拼接 `_hard`(景别词+品牌专有+brew button 正面面板)。
2. **指纹换档**:定向重试把 `_ci += "-retarget1"`——否则下次重跑
   判 fresh 复用旧 clip,定向重生成自闭环失效(钱花了内容没换)。
3. **attempts 留痕**:`{"vlm_review": "critical→定向重生成",
   "codes": [...]}`——运营可分辨「QC 重试」与「定向重生成」。

测试(TestTargetedRegeneration×2):critical→变体重生成→通过落账
(断言 prompt 含 FIXED camera、attempts 带 codes);持续 critical
→ 不 silently 放行, shots_review 落记录交 assemble 拦。

## 61b:首帧锚定图 brew button 特写(pipeline_runner.py)

AGNES 2.5 **以首帧为条件生成**——图里键位对了视频里就对了。按键类
scene(cu/ecu/mcu)的图像 prompt 追加:"tight close-up of the finger
pressing the brew button on the machine's FRONT panel, with the
'<brand>' logo printed directly beside it — front-facing and
centered, clearly NOT a side-panel control"。
