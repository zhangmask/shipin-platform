# 轮62：seed 维度重生成——S03「侧面按键」finding 确认消除

> 2026-09-25。验证目标(上一轮留给模型侧的判定):S03 侧面按键 finding 在 prompt 四层策略
> (景别前移/品牌否定/按键硬约束/首帧锚定特写+定向重生成)全部用尽后,换**采样维度**
> (seed)能否消除。结论:**能——VLM_BREAK 与"位置不符"两条 critical 确认消除**。

## 一、方案探测(先证明有路可走再动手)

| 候选 | 结果 |
|---|---|
| 本地 MiniMax-H3 | `api_reachable()=False`,本机不可达 |
| agnes-video-2.0 | 503 `model_not_found`(无可用通道) |
| agnes-video-2.5-flash + seed | **200**——带 seed 与不带 seed 提交均正常返回,无 unknown-field 拒绝 |

## 二、实现(24 行,两文件)

1. `generate_video_agnes` 增加 `seed: int | None = None` 参数:
   - **仅 v2.5 协议注入** `body["seed"]`(v2.0 不认,注入会被拒)
2. `pipeline_runner` attempt 阶梯接入 seed(与 prompt 变体正交的采样维度):
   - attempt 0 不换(保留首轮原样),attempt≥1 按 `4242 + attempt*7919`
   - 定向重试指纹同步换档:`_ci += "-retarget1-s{同档seed}"`——指纹不带 seed
     则下次重跑判 fresh 复用旧 clip,换 seed 自闭环失效(钱花了,采样面没换)

**测试**:`test_seed_ladder_reaches_generator`——断言 seed 真的传到生成器入参
(不只数 attempt 次数)。定向路径(诊断 critical)只额外重试一次:attempt 1 仍
critical 即落记录交 assemble 终审,`seeds == [None, 4242+7919]`。

## 三、真链路验证(tvc-07431,竖版 720×1280,5 镜)

第一轮 generate:S03 attempt 0 过了 clip QC 但 VLM 诊断仍 critical(本次是
SHOT_STORY_MISMATCH)→ 定向重试点火,但 **AGNES 视频上游在窗口内 503 全拒**
(attempt 1/2 各烧 2 次提交 + 1 次空返回),generate 按 fail-closed 返回失败、
原因完整留痕。第二次 generate(约 4 分钟后)attempt 0 遭遇同样 503、attempt 1
(seed 12161)生成成功过 QC。第二次成功 generate 后哈希对齐(全缓存命中)→ assemble。

## 四、测试隔离缺陷(全套回归抓出,同轮修复)

全套回归(带 E2E 不过滤)`test_critical_review_triggers_variant_regen` 挂:
单跑/文件跑/带 key 单跑均过,全套必挂——**顺序依赖污染**:
test_api*/test_variants 在收集期 `import api`,api 模块导入时
`load_dotenv()` 晚于 conftest 把 .env 的真 AGNES_KEY 灌进进程环境,
之后所有用例的 `vlm_same_scene`/`vlm_morph_check` 全部真打网络。
实测链条:VLM 可达时,testsrc2 假素材 vs 真实参考图**必判
"different"**(画面级差异,VLM 原文可复现)→ REF_VLM_MISMATCH
critical → attempt 0 QC 判 fix → 定向重试永不触发 → 断言挂;
VLM 恰好不可达时才过。**整套回归在烧真钱,且结果三分裂**。

修复:conftest autouse `monkeypatch.delenv("AGNES_KEY")` 逐例剥键
(setdefault 类钉法救不了晚于 conftest 的注入),真链路 E2E 用
`@pytest.mark.real_network` opt-in;标准回归 `-m "not real_network"`
(精确排除,不再靠 `-k "not e2e"` 误伤 e2e-* pid 用例)。回归钉:
`TestEnvIsolation` 双测(毒化环境可见 + 下一用例必须干净——
反事实验证:无 fixture 时第二个断言立即挂)。

**连带第二波**:剥键后 `/api/generate/image` 的 auto 模式落 PIL 占位
(无 key 不路由到生成器),`test_generate_image_{backend_error,value_
error}` 两个错误映射测试的 mock 永不被调用——它们此前也一直**依赖
泄漏的真 key** 才走到被测分支。修:payload 显式 `"mode": "agnes"`
(无条件走生成器路径),把"测错误映射"与"key 是否存在"解耦。
这也说明污染面比初见时大:凡是 auto 模式端点测试都可能隐性带 key
依赖,剥键后必须逐个复核(本轮全套回归只此两条,已全修)。

## 五、结论

- **S03 侧面按键复杂 finding(2 条 critical)经采样维度重生成后确认消除**——
  轮61"模型指令遵循上限"的判定被修正为"prompt 平面内上限,换采样面有出路"。
- 剩余 S03 蒸汽 finding 是分镜明文预期(`scene: 热气流升腾` / `effect: Steam
  begins to rise from the spout`)的真实缺口,非误报;是否再压一轮 seed 阶梯
  (12161→20080 还有一档未在本镜用过)留待下一轮评估。
- 上游 503 期间全部路径 fail-closed:无静默放行、无 fake pass,attempts 逐条
  留痕(网络异常/定向重生成/空返回三者可区分)。
