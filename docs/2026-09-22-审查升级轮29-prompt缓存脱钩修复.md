# 审查升级轮 29（2026-09-22）：prompt 阶段缓存脱钩修复（内容哈希判定）

## 缺口：审查过的输入 ≠ 实际使用的输入

`run_generate_phase` 的 prompt 阶段重审条件是
`row.status != "PASS"`——**只看状态不看内容**。分镜文本变了但
shot_id 集合不变时（典型：`_bind_brand` 在 generate 内部把「XX咖啡」
占位符绑成真实品牌名、`/rewrite` 改了主体描述），新派生 prompt 被
整个丢弃，739-744 行直接从盘上读**旧** image_prompt/video_prompt 用于
生成：

- 品牌注入（首/尾镜 prompt 里的 brand label）丢失 → 要到终审
  BRAND_MISSING 才炸，而 generation 的钱已经花完；
- prompt 阶段对新输入再无审查（`_iterate` 不被调用）——「审过的
  输入 ≠ 实际使用的输入」，缓存名不副实。

## 改动（pipeline_runner.py）

- 新增 `_prompt_stage_stale(row, data)`：派生数据哈希与已审
  artifact_hash 不一致 → 脱钩（行缺失/哈希为空等旧数据同样判脱钩，
  走安全方向重审一遍）；
- prompt 阶段循环：`_prompt_stage_stale` 或状态非 PASS → 重跑
  `_iterate`（新输入重新过审 + 落盘），否则才是真缓存命中跳过。

判据与 `_iterate` 记帐用的 `stable_artifact_hash(data)` 同源，一致
即命中、不一致即重审。

## 测试（TestPromptStageCache，4/23 in suite）

同哈希 → 非 stale（真缓存命中）；输入变 → stale；空哈希（旧数据）
→ stale；非 PASS 行 → 非 stale（交由主逻辑处理）。
