> 日期：2026-09-18
> 目标：把 shipin-platform 从"受控流水线 + 前端壳"演进为完整平台级形态。
> 现状基线：8 阶段状态机 + 三重确认闸 + 成本记账/预算硬闸 + 事件留痕 + MCP stdio 网关(10 工具)
> + 防篡改封印 + React 前端(6 面板)，全量回归 **300 passed**，封印 58 文件一致。
> 铁律（沿用并强化）：

1. **先调研，后动工**：每个批次开工前，先下载/检索对应 GitHub 高 Star 或社区热门项目，
   读源码 + 抓 Issues，把"它怎么做的、为什么好、哪里不适合我们"写成 调研小节 附在本计划
   对应批次下（范例：`docs/2026-09-17-C5-阶段协同与人工介入-调研与设计.md`），批准后才改代码。
2. **不删功能、只封入口**：移除/废弃能力一律走 410/弃用标注，禁止悄然删除。
3. **回归门槛**：新批次完成后全量 pytest 必须保持绿（当前 300），封印必须重建并 `--verify`。
4. **安全不回退**：任何新代码继续遵守 SSRF 白名单 / 参数数组 subprocess / 非本地不发外部请求。
5. **AI 只有工具权**：平台工具的修改入口只有人（`platform_integrity.py --build`）。

### P0 鉴权与项目管理（最小安全边界）🔒
**调研小结（2026-09-18，官方文档核实）**：n8n 按用户发 key（X-N8N-API-KEY、只显示一次、可吊销；非企业版 key 默认全量权限——不借鉴）；Dify 按 App 发 key（Bearer、可停用，scoped key 可限定单个知识库——"App 即资源"的最小权限粒度值得借鉴）；Windmill 用 domain:action:resource 三元组 scope、write 隐含 read、可过期吊销——scope 分级思想可借鉴，但铺得最细不照搬；Langflow key 入库加密、记录 total_uses/last_used_at，但无过期无 scopes。**四个项目的共同短板：自托管无内置限流、审计弱——这是我们的能力位（P7 补）**。
**待调研高星项目**：n8n（API keys/用户体系兄弟作品）、Dify（API 密钥与 App 隔离）、Windmill（角色/权限模型）、Langflow（API Key 设计）。
**实现要点**：
1. `X-API-Key` 中间件：管理端主 API key（环境变量 SHIPIN_ADMIN_KEY，不落库）+ 项目级 key（库内仅存 sha256 指纹，明文只显示一次——对标 n8n/Dify）
2. scope 三级：read / write / admin（对标 Windmill 分级）；key 可绑定 project_id，路径级强制只能访问绑定项目（对标 Dify scoped key 最小权限）
3. 无 key → 401；健康检查 `/api/health` 豁免；`SHIPIN_AUTH_MODE=off` 供测试/本地
4. `projects` 表加 `owner` 列（迁移兼容旧库）；`/api/projects?mine=1` 过滤 + 分页
5. 平台管理端点 `/api/platform/keys`（签发/列表/撤销，admin 专属）；事件留痕 caller 审计（P7 导出）
**验收**：未带 key 调用 `/api/pipeline/generate` → 401；带只读 key 改写 → 403；带回写 key 通过；绑定项目 key 越权访问其他项目 → 403；既有 300 测试适配后仍绿。

### P1 异步任务与进度流（长任务不阻塞）
**调研小结（2026-09-18，GitHub API 星数 + 官方文档）**：Celery(28.9k★)/Dramatiq(5.3k★)/RQ(10.7k★) 都要求 Redis/RabbitMQ broker；arq(3.0k★) 已进 maintenance-only；Huey(6.0k★) 支持 sqlite 后端，是无 broker 现成方案；Kestra(28k★) 是 JVM 重守望编排，仅借鉴其"17 态执行状态机 + state history"的严谨；Airflow(46.8k★) 元数据库即单一事实源 + 心跳判活 + UP_FOR_RETRY 参数化重试 —— **最值得借鉴的是"DB 即状态机 + heartbeat 心跳超时检测 + 幂等重试位"**。各库均无内建进度百分比（Celery 靠 update_state(meta)、RQ 靠 job.meta），前端进度获取清一色轮询（Airflow UI/Kestra UI/RQ dashboard），无默认 SSE/WebSocket。**结论：本平台选"自研线程池 + SQLite 任务表"（零外部基础设施、状态/进度/幂等键用 SQL 天然支持；视频任务不适合 fork/prefork 显存复制）；前端 1-2s 轮询 /api/tasks/{id} 即可，不引 SSE（跨 worker 需 Redis 反而引 broker）**。
**实现要点**：
1. `services/task_store.py`：tasks 表（task_id/kind/caller/status queued→running→success|failed|retry/attempts/max_retries=2/heartbeat_at/error/对应 project）+ 全局 ThreadPoolExecutor(max_workers=2)；进度=阶段映射（brief 10 → script 25 → … → post 100），由轮询 stage_runs 自动推导，零侵入
2. generate/assemble 增加 `?async=true`：同步语义保留（MCP/既有测试不变），async 返回 202+task_id；`GET /api/tasks/{id}`（含 progress/stage）、`GET /api/tasks?project_id=`、`POST /api/tasks/{id}/retry`（幂等重试，attempts<max_retries）
3. 启动时扫描：heartbeat 超期的 running → failed(crashed)，可重试
4. 前端 `runStage` 改用 async 车道 + 进度条（阶段名+百分比），MCP generate/assemble 保持同步
**验收**：`generate?async=true` 返回 task_id 且 body 里 progress 随轮询推进至 100/success；心跳失效任务标记 failed 且可 retry；同步调用行为与回归完全一致。

### P2 产物版本化与回滚（AI 改错可复原）
**调研小结（2026-09-18）**：DVC（16k★）用「内容哈希即版本」——`.dvc` 文件只存 path+md5/sha256，缓存按内容寻址，切换版本=换指针，`dvc checkout` 回滚（官方文档核实）；n8n executions 每次运行保存全量节点数据供 Editor 回放（官方文档核实）；Litestream 是 SQLite WAL 时间线。**共性：元数据索引 + 内容寻址 + 全量快照。本平台 JSON 产物直接用 SHA-256 内容哈希去重，重复写不产生新版本；回滚照 dvc checkout 语义写回旧内容。**
**实现要点**：
1. `data/projects/<id>/versions/<stage>/v<n>.json` 全量快照：`_save` 统一钩子（script/storyboard/brief/image_prompt/video_prompt），内容哈希（SHA-256）去重——同内容不产生新版本（对标 DVC 缓存复用）
2. `versions.json` 索引：`{stage: [{version, ts, hash, caller, bytes}]}` —— 由 `artifact_store.snapshot()` 统一写入
3. `GET /api/pipeline/{id}/versions?stage=` 列表；`POST /api/pipeline/{id}/restore` {stage, version} → 写回旧版 + 清确认 + 闸门重置 + 失效下游（复用 C5 rewrite 语义）+ `stage_restored` 事件；回滚本身也产生新版本头（历史可追溯）
4. 前端分镜面板加「回滚到上一版本」按钮（带确认），版本数随卡显示
**验收**：改写 script 后 versions 多一条；restore 后旧内容可见且下游 BLOCKED；同内容重复写不产生新版本；回归保持绿。

### P3 全局成本与配额（FinOps 化）
**调研小结（2026-09-18）**：OpenCost（K8s 成本 showback 事实标准）的做法是「按时间窗口按维度做 allocation 聚合」——同一份明细，可切成 namespace/deployment/时段；聚合结果喂报表；预算超支告警。云厂商（AWS Budgets/Azure）模式也是「月度硬预算 + 超限告警/拦截」。**本项目落到：同一台账 cost.json，按 项目×月份/近7日 两种维度聚合 + config/global_budget.json 月度硬闸（入队即拦，与单项目闸并列）。**
**实现要点**：
1. `config/global_budget.json`：全局月度预算；`POST /api/platform/budget`（仅 admin key，见 P0 中间件分层）+ `GET /api/platform/costs`（aggregation: total/月/近7日/top 项目/exceeded 状态）
2. 聚合与硬闸在 `services/costing.py`：`global_cost_summary()`（OpenCost allocation 思想）+ `global_budget_exceeded()`
3. 全局超限 → 新建 generate/assemble 时 422（单项目闸之前先查全局闸）+ `budget_exceeded` 事件；账户随成本面板暴露
4. 前端新增「平台成本总览」面板（admin 可见；strict 下无权限给出提示）
**验收**：造 3 个项目不同成本，聚合正确（增量断言）；全局预算设为小于当前累计 → 下一个 generate 被 422；清除 → 解闸；回归保持绿。

### P4 MCP/AI 接入深度（AI 全可见）
**目标**：把 C5 能力（产物读取 → 编辑重跑 → 事件 → 预算调节 → 预览）全部暴露给外部 AI，补齐 G6。
**实现要点**：
1. MCP 工具从 10 → 16：`list_events`、`get_artifact`、`rewrite_stage`、`set_budget`、`preflight`、`preview_frames`
2. `project_status` 增强：返回 gates 待确认清单 + artifacts 清单 + budget + 最近事件摘要（AI 决策依赖）
3. `AGENT_GUIDE.md` 重写为「AI 工作流」：AI 是沙盘看板上的执行者,确认才落闸
**验收**：模拟 Codex 调用 6 个新工具各一次,服务端事件/产物/预算均正确落账；`project_status` 摘要可读。

### P5 前端产品化
**目标**：从"单页仪表盘"到"看板"。
**调研吸附窗口**：n8n Editor UI（节点流）、Dify Studio（画布）、ComfyUI canvas（节点内改参重排）。
**实现要点**：
1. 引入 React Router：`/`项目列表 → `/projects/:id` 流程球看板（8 阶段时间线 + 每阶段卡片：产物/闸/重跑）
2. 阶段卡片内嵌产物浏览（JSON 树/文本切换）与「重跑」按钮（复用 P2 restore）
3. 版本 diff 视图（新旧 JSON 对比标注）+ 事件瀑布图
4. 全局成本面板（P3）+ 鉴权登录页（P0）
**验收**：桌面浏览器遍历项目全流程（new→text→confirm→generate→assemble→预览→回滚→重跑）无控制台报错；build 无 warning。

### P6 部署与运维（一键可跑）
**目标**：任何人 clone 后 `docker compose up` 即可看到平台
**实现要点**：
1. 多阶段 Dockerfile：`python:3.12`（依赖锁 + 平台源码）与 `node:20`（web build）→ 单镜像
2. `docker-compose.yml`：api 服务 + named volume（data/ 持久化）+ healthcheck
3. `start.sh`/`start.ps1`：本地无 docker 时一键起 uvicorn
4. 根目录清理：`out_test.mp4`、`s01_check.txt`、根 `storyboard.json`、根 `projects/`、`project 上传残留` 全部移入 `legacy_archive/`（回归后）
5. README 重写：去掉 CLI 引导，改为「网页 / MCP / API 三层入口 + 鉴权配置 + 部署」
**验收**：docker compose 起服务 → `/api/health` OK → `/ui` 打开 → 一个项目全流程通过 → 重启数据仍在。

### P7 安全硬化与审计导出
**调研**：OWASP API Security Top 10、FastAPI 安全实践、认证限流中间件实现对比（slowapi / 自研 token bucket）。
**实现要点**：
1. 限流：每 API key 每分钟 N 次（token bucket，内存实现，写审计）
2. `GET /api/platform/events.csv|json`：全量事件导出（含 caller/ip）
3. CORS 收紧为白名单（默认仅同源），预检拒绝配置之外的 origin
4. `POST /preflight` 扩展：限流器状态、磁盘占用、日志体积
**验收**：1s 内连打 50 次 → 429；导出 CSV 带表头且可导入 Excel；跨域请求被拒。
