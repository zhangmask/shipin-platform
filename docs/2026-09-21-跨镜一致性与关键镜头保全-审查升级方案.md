## A. 跨镜人物一致性检测

### A.1 行业通行做法（开箱可抄，按"审查方"视角排序）

| 方法 | 仓库/出处 | 输入 | 输出 | 阈值参考 | 我们怎么用 |
|---|---|---|---|---|---|
| 人脸嵌入（ArcFace 系） | `deepinsight/insightface`（29.8k★，`buffalo_l/w600k_r50` onnx 模型）；`serengil/deepface` 阈值表 | 裁人脸图 → 512 维 L2 归一嵌入 | 余弦相似度 [0,1] | deepface 预标定：`ArcFace: cosine 0.68`（等价余弦相似度 ≥0.32 判同人）；`buffalo_l: 0.54`；**VBench-2.0 human_identity 直接用 0.4，低于 0.4 判"换脸"** | **主证据**，无 GPU 走 onnxruntime CPU（单帧 ~0.2-0.5s） |
| 人物 ReID | `KaiyangZhou/deep-person-reid`（超4.9k★，OSNet 权重）；DeepSORT/StrongSORT 系引用 | 全身裁图 → 512 维嵌入 | 余弦相似度 | OSNet Market1501 内部相似度 ~0.5-0.6 区分度高，保守阈值 0.5 | 仅"看不到脸"（远景/背影/遮挡）时兜底；全片人头=全片不需要 ReID |
| 服装/颜色直方图 | 自定义（OpenCV `calcHist` + `compareHist`） | 人物 bbox 下半 60% 区域 HSV 直方图 | Bhattacharyya 距离 [0,1] | 0-0.15 同装；0.15-0.3 可疑；>0.3 换装 | 次级证据，负责"换装"维度，廉 |
| VLM 跨帧对比 | GPT-4V 类（平台已有 AGNES `_ask_vlm`）；VBench-2.0 `human_clothes.py` 用 LLaVA-Video 问 3 个 yes/no | 2-8 帧拼包 | 结构化 JSON（same/different + 理由） | VBench 模板照抄（见 A.4） | 复核层 + 兜底，只在确定性裁决"不一致"或"无脸"时触发，节省费用 |

**不要抄**：生成端一致性（IP-Adapter / InstantID / AnimateAnyone）是生成时保证，与审查无关——只提一句防误导。

### A.2 确定性主链：InsightFace / ArcFace 人脸嵌入

```python
# 环境：pip install insightface onnxruntime（无 GPU 可用，CPU 即可）
# 模型：buffalo_sc 或 buffalo_l（自带 RetinaFace 检测 + ArcFace 识别，onnx）
import insightface
app = insightface.app.FaceAnalysis(name="buffalo_l", providers=["CPUExecutionProvider"])
app.prepare(ctx_id=-1, det_size=(640, 640))

def face_embed(frame_bgr) -> list[dict]:
    """返回 [{bbox, emb, kps, score}]，score<0.5 丢弃；无脸返回 []"""
    return [f for f in app.get(frame_bgr) if f.score >= 0.5]

def face_sim(e1, e2) -> float:
    import numpy as np
    a, b = np.array(e1), np.array(e2)
    return float(np.dot(a, b) / (np.linalg.norm(a) * np.linalg.norm(b)))  # 余弦
```

**输入要求（抽帧）**：
- 每镜抽 **开/中/尾 3 帧**（与现有 `FRAMES_PER_SHOT=3` 对齐；`hard_gates._context_frames` 现成复用，避开 0.45s 叠化带）。
- 对比粒度：①**相邻镜**（跨镜接缝是换脸重灾区）：镜 N 的尾帧 vs 镜 N+1 的头帧 + 各取中帧；②**主角档案**：全片第一个检测到单张高分脸的镜头建立人脸嵌入档案，其余所有镜头中帧与该档案比较（覆盖非相邻换人，如 A 镜 → B 镜 → A 镜改人）。
- 每镜至多 4 次人脸推理 → 10 镜 40 次/片，CPU 上 20-40 秒，可接受。

**判定与阈值（VBench-2.0 + deepface 双源标定）**：

```python
FACE_SIM_PASS   = 0.55   # ≥0.55 同人（预测优化值，参考 arcface 0.68/buffalo 0.54 → sim≥0.45 即同人，取 0.55 求严格）
FACE_SIM_WARN   = 0.40   # [0.40,0.55) 预警 → 交给 VLM 复核
FACE_SIM_FAIL   = 0.40   # <0.40 判换脸（与 VBench human_identity 阈值一致）
```

结果合成（避免单帧误报）：同一镜 N 帧中**任一帧**比对 < FAIL → `IDENTITY_SWITCH`（critical，必须重生成）；全镜 [WARN, PASS) → `IDENTITY_DRIFT`（suggestion，VLM 复核后定论）；某镜头检不出单脸 → 记 `FACE_UNCLEAR` 并降级到服装+ReID/VLM，不硬拦。

### A.3 服装/道具一致性（无 VLM 的"换装"检测）

```python
def apparel_descriptor(frame, face_bbox):
    """人脸框 (x1,y1,x2,y2) 向下延伸 2.5~4.5 倍高 = 躯干带；HSV 直方图 32x24x24，归一化"""
    h = face_bbox[3]-face_bbox[1]
    trunk = frame[max(0,int(y2+0.4*h)):int(y2+3.5*h), int(x1-0.2*j):int(x2+0.2w)].copy()
    return cv2.calcHist([trunk],[0,1,2],None,[32,24,24],[0,180,0,256,0,256])
def apparel_sim(h1,h2): return 1 - cv2.compareHist(h1,h2,cv2.HISTCMP_BHATTACHARYYA)
```

阈值：`BV ≤0.15` 同装；`(0.15,0.30]` → `COSTUME_DRIFT`(suggestion)；`>0.30` → `COSTUME_SWAP`(critical)。注意同人不同机位（正侧背）会自然漂移，所以它只做次级证据：**人脸通过 + 服装 FAIL → 仍判 critical**（影视出片不允许主角换装跨镜）；人脸 FAIL 时它被用于定位"到底换的是头还是衣服"（诊断信息）。

补充"统一装束描述"低开销通道：每镜末帧裁剪过的人物送到 VLM 问"请用 20 字内描述此人发型/服装颜色款：'"，把 N 镜的 N 段描述做文本相似（`difflib`/编辑距离），描述差异 > 阈值触发 `COSTUME_DESC_DRIFT`——实现成本低但 LLM 文本漂移不可控，标为 P2 可选。

### A.4 VLM 复核模板（可直接粘贴；复用 `hard_gates._ask_vlm`）

```python
SAME_PERSON_PROMPT = (
  "图1、图2 是同一部影片中先后两个镜头里的人物。仅依据画面事实判断："
  "是否为同一人（同一张脸，同一发型；着装有 90% 以上一致可接受微差）。"
  "注意：构图、景别、光线差异不考虑；换人、换发型、换服装颜色/款型均为不一致。"
  '返回严格 JSON：{"same": true/false, "spec": "<不一致的点：脸/发型/服装/身材>", "reason": "..."}'
)
CLOTHING_PROMPT = ...  # 专问服装：只要描述"上半身颜色+下半身颜色+长短款"是否一致
```

聚合规则：多对（N-1 邻接对）逐对问，`same=false` 且理由 consistent → `IDENTITY_SWITCH`（critical）或 `COSTUME_SWAP`；只有 1 对且 spec="光线/画质" → 降级 suggestion 请人工复核。

VLM 复核的调用量设计：全程人脸通道 PASS 时**不调 VLMR**（省 95% 费用）；只在 FAIL/WARN/无脸区域触发、每次 1 张今 3 张图。

## B. 关键镜头保全检查清单

### B.0 前置：分镜契约需要增加"关键标记"

`src/shipin_platform/contracts/stages.py` 的 `ShotContract` 目前只有 `subject/motion/scene/camera`，**没有任何"必须保全"字段**——这是盲区 1 的根。新增：

```python
@dataclass(frozen=True)
class ShotContract:
    ...
    key_level: str = "normal"        # "normal"|"hero"|"brand"|"prop"  关键标记
    key_entities: tuple = ()        # 本镜必须出现并保持的主体：("女主演面孔","杯身LOGO","咖啡豆道具")
```

下游：`storyboard` 阶段产出时由用户/LLM 标注 `key_level`；`clip_qc`/`final gate` 只对 `key_level != "normal"` 的镜头开 B 清单（省钱）。

### B.1 每关键镜的 5 项检查（对应直接可用的判定）

| # | 检查 | 方法 | 判定 | 失败码 |
|---|---|---|---|---|
| B1 | 镜头在场 | C 节时间轴对账（shot_id 全集） | 缺镜 | `SHOT_MISSING` |
| B2 | 关键人物脸保全 | A 节人脸档案 vs 本镜 3 帧（用分镜给的"角色参考帧"或剧本首镜存档为基准） | 任一帧 sim < 0.40 | `KEY_FACE_LOST`；[0.40,0.55) → `KEY_FACE_DRIFT` |
| B3 | 品牌产品/关键道具保全 | ①参照帧 pHash ≤ 28（同主体不同机位）；②VLM `PROP_SAVE_PROMPT` | VLM same=false | `KEY_PROP_LOST` / `KEY_ENTITY_SWAP` |
| B4 | 服装/身体外形保全 | A 节服装直方图 vs 基准镜（分镜首个该角色镜） | >0.30 | `KEY_COSTUME_SWAP` |
| B5 | 变形/怪物化 | 复用 `clip_qc.vlm_morph_check`（现成）+ 跨镜版：主角脸两次出现时检测评级均值跳跃 | morph=true | `KEY_MORPH` |

### B.2 VLM 模板（关键物件/主体保全，同一"图目标"模式可复用）

```python
KEY_OBJECT_PROMPT = (
  "图1 是分镜/剧本指定的【关键参照】；图2 是该场景生成后的实际帧。"
  "仅依据画面事实回答：图2 中是否完整出现同一关键主体：{key_objects}；"
  "主体数量、外观细节（颜色/材质/文字/形状）是否与图 1 一致？"
  '返回严格 JSON：{"present": true/false, "mismatch": ["<该主体出现不一致>"], "reason": "..."}'
)
```

- `present=false` → `KEY_*_LOST`（critical，重生成该镜）；`mismatch` 非空且含"外观细节"句法 → `KEY_PROP_CHANGED`（critical）。
- 输入：参照帧 = 分镜所带参考图（已有 `reference_image` 链路）或前一个含该主体的镜头的中间帧。

### B3 确定性补充（免费通道，先于 VLM）

- **关键帧返回穿越检**：某一镜首帧与首镜（含主角/产品）首帧的 SSIM/pHash 检查——"同机复位重拍"时值很高（B3 覆盖）。
- **主体存在性（无 VLM 版）**：`yolov8n.pt` CPU 检测（约 100ms/帧）查关键框类别：主角 → "person"，品牌 → "cup/bottle/box..."；主干分类不存在 → `KEY_OBJECT_DETECT_MISS`（warning，转 VLM 二次裁决）。

## C. 素材复用 / 漏镜检测（确定性，无 VLM）

### C.1 伪装复用：跨镜 pHash 近邻（补现有 `REUSE_LIMIT` 漏洞）

现状：`check_timeline` 只按 **src 素材名** 计数（>3 次/间距 <20s 才拦截）——如果生成器把同一个画面重复生成为"两个不同文件"（排队重出/种子复用），现有规则完全看不到。

```python
import imagehash
from PIL import Image
# 升采样：每个镜头抽 ≤4 帧（0.1/0.4/0.6/0.9 或 fps 采样），缩到 32 宽
h1, h2 = imagehash.phash(Image.open(f1), hash_size=16), imagehash.phash(Image.open(f2), hash_size=16)
dist = h1 - h2            # 汉明距离，0-256 空间（16x16=256）
def same_frame(dist):     return dist <= 12   # ≈同画面（改色不算，见下）
def near_dup(dist):       return dist <= 24   # 同一机位近似重拍（构图同但纹理不同）
```

| 对 | 判定 | 失败码 |
|---|---|---|
| 任意两镜存在 ≥2 帧对 `same_frame` 且镜头时长重叠 >10% | 复用是真 | `SHOT_REUSED`（critical） |
| `near_dup` 的帧对占两镜头可检帧数 >30% | 疑似复用 | `SHOT_SIMILAR`（warning，VLM 可复核是否刻意"回环"） |
| 显式"回环/回声镜"（脚本标注 echo 的镜头） | 允许，但沿用现有 ≥20s 间隔约束 | — |

参考仓库：`idealo/imagededup`（pHash/dHash/CNN 查重，pHash 距离经验阈值 ≤5~8/64bit 视为同一画面；我们取 hash_size=16 把区间拉宽以免误杀）；`AB-Video-Deduplicator`（抽帧哈希 + 直方图双检，可抄其"逐段比对"骨架）。前者是 CPU 友好的基础库。

补充通道（防止"换配色去重"）：对 `same_frame` 已入围但颜色差异大（Bhattacharyya > 0.3）的对，标记 `REUSE_RECOLORED`（建议人工）——对应日本同斜曲线。

### C.2 时间线对账（防"剧本 10 镜成片 8 镜"）

在 `hard_gates` 加三个纯统计项（全部零调用）：

```python
script_ids    = {s.shot_id for s in storyboard.shots}
timeline_ids  = {c['shot_id'] for c in timeline}   # contracts 已约束 timeline 每 clip 有 shot_id
missing = script_ids - timeline_ids                # 漏案！
extra   = timeline_ids - script_ids                # 插入案！（拼接投机）
assert missing == set() and extra == set()
```

| 统计项 | 判定 | 失败码 |
|---|---|---|
| `missing` 非空（剧本镜头未进时间线） | critical | `SHOT_MISSING` |
| `extra` 非空（时间线多了剧本没有的镜头） | critical | `SHOT_INJECTED` |
| 总时长：`Σ(end-start) vs 剧本 Σduration` 偏差 | >3% | `DURATION_MISMATCH`（已有，保留） |
| 每镜实际在轨时长 vs 剧本 `duration_sec` | 偏差 >0.7s（对齐 `clip_qc.duration_tolerance`） | `PER_SHOT_DURATION` |

每镜在轨时长 = timeline 里该 `shot_id` 的连续块 `end-start` 总和；若某镜在时间线上被"截成两半插在两个位置"（同样镜被切碎垫时长），按 `SRC_UCE` 已 CheckMarker（`src` 名重复次数+跨度规则扩展：>1 段且段间 >5s → `SHOT_SPLICED` warning）。

### C.3 帧级差异（光学 diff）与"同机位复位重拍"

- 逐帧 diff 工具：`ffmpeg -vf  psnr` / `ssim`（官方滤镜，零依赖）或 `skimage.metrics.structural_similarity`。
- 语义判定：**SSIM ≥ 0.98** 同帧（仅压缩差）；**0.90-0.98** 近似同帧（码率差/尺寸差，核查是否有意）；**< 0.85** 视为不同画面（不用于判定，仅 API）。
- "同机位重复摄影"场景判断是合成专用：同一主体+背景，不同动作 → 驱动 B3 的 `KEY_PROP` VLM 复核（若主体是标称不变的）。
- 现成"逐镜 diff"小仓库（无重依赖）：`VideoEncodingComparison`、`cframes` 等 ffmpeg 滤镜薄封装（PSNR/SSIM），直接抄其"同帧对拍"思路；可靠做法是把阈值写进我们的 `review/` 代码，不引第三方大项目。

## 附录：实现排期与验收

- 验收一（跨镜换头）：脚本里含 6+ 镜同一主角，人工把第 3 镜替换成另一人脸素材 → 审查必须报 `IDENTITY_SWITCH` 且定位到镜 3。
- 验收二（关键镜头丢主体）：分镜将某镜标 `key_objects=["杯身LOGO"]`，生成包含"无 LOGO 的场景" → 审出 `KEY_*_LOST`。
- 验收三（复用/漏镜）：把第 5 镜素材复制改名插到第 8 位置 → 报 `SHOT_REUSED`；把剧本某镜从 timeline 删除 → 报 `SHOT_MISSING` 而不许 pass。
